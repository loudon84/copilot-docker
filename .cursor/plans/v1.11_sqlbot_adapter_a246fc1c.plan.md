# v1.11：bi-strategic-office 接入 SQLBot 智能问数

## 现状摘要

当前 v1.10 专家包位于 `expert-templates/bi-strategic-office/`，核心是自研 `hermes-finance-bi-plugin`（21 个文件），包含 catalog/planner/compiler/executor/policy 等完整问数引擎，注册 6 个工具，直连只读数据库执行 SQL。

## 改造核心

用 SQLBot 外部服务（通过 MCP 调用）替代自研问数引擎。新建 `hermes-sqlbot-adapter` 插件，仅负责 MCP 连接/会话管理/查询保护/结果标准化，SQLBot 负责 SQL 生成与执行。

## 关键差异对照

- **工具数量**：6 个 --> 4 个（去掉 `catalog_search`、`validate_result`、`export_result`，新增 `reset`）
- **插件目录**：`plugins/hermes-finance-bi-plugin/` --> `plugins/hermes-sqlbot-adapter/`
- **数据源配置**：`FINANCE_BI_DSN` 等直连参数 --> `SQLBOT_MCP_URL` + `SQLBOT_USERNAME/PASSWORD/WORKSPACE_ID` 等
- **状态存储**：`finance-bi/state/finance_bi.db` --> `sqlbot-adapter/state/sqlbot_sessions.db`
- **语义目录**：本地 `runtime/semantic/` --> SQLBot 内部管理，不再需要
- **依赖**：sqlalchemy/pymssql/sqlglot --> httpx（MCP client）+ aiosqlite

## 影响范围

所有改动限定在 `expert-templates/bi-strategic-office/` 内，不修改公共脚本、不影响其他专家。

### T05：实现 MCP Client (`client/mcp_client.py`)

- 使用 `httpx` 调用 SQLBot MCP 端点（`SQLBOT_MCP_URL`）
- 封装 4 个内部调用：`mcp_start`（登录）、`mcp_question`（提问）、`mcp_ws_list`、`mcp_datasource_list`
- Token 缓存：登录后保存 `access_token`，过期自动重新登录
- 超时：`SQLBOT_REQUEST_TIMEOUT_SECONDS`（默认 120s）
- 重试：网络异常重试 1 次
- 错误转换：SQLBot 原始错误 --> `ErrorCode` 枚举
- **关键约束**：不暴露 `access_token`、`chat_id`、用户名/密码给模型

### T06：实现 Session Store (`session/session_store.py`)

- SQLite + WAL 模式
- 路径：`/data/hermes/sqlbot-adapter/state/sqlbot_sessions.db`
- 表字段：`hermes_profile`、`hermes_session_id`、`hermes_user_id`、`sqlbot_chat_id`、`sqlbot_workspace_id`、`sqlbot_datasource_id`、`token_encrypted`、`token_expires_at`、`last_query_id`、`created_at`、`updated_at`、`expires_at`
- 映射键：`(hermes_profile, hermes_session_id, hermes_user_id)`
- 会话 TTL：`SQLBOT_SESSION_TTL_SECONDS`（默认 86400）
- 所有写入 commit 后再返回
- `reset()` 方法清除映射

### T07：实现查询保护 (`security/`)

**query_guard.py**：
- SQL 只读校验（使用 `sqlglot` 解析 SQL AST，仅允许 SELECT / WITH...SELECT，拒绝 INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE/CALL/COPY/多语句）
- 显式标识符提取：从用户问题中提取 `ar_trx_number = XXX`、`凭证号 XXX`、`订单号 XXX`、`客户编号 XXX` 等显式值
- 过滤保留检查：检查 SQLBot 返回的 SQL 是否保留了这些显式值，未保留时返回 `FILTER_NOT_PRESERVED`

**result_guard.py**：
- 明细查询约束：无精确编号/日期范围/客户/主体过滤时返回 `DETAIL_QUERY_REQUIRES_FILTER`
- 行数限制：默认返回模型 100 行（`SQLBOT_MODEL_RESULT_ROWS`），最大 500 行（`SQLBOT_MAX_RESULT_ROWS`）

### T08：实现结果标准化 (`normalizer/result_normalizer.py`)

将 SQLBot MCP 返回转为 PRD 第 14 节标准结构：

```python
{
  "success": True,
  "query_id": "fbq_xxx",
  "title": "...",
  "datasource": {"key": "...", "name": "..."},
  "query": {"question": "...", "sql": "...", "filters": [], "row_count": N, "truncated": False},
  "columns": [{"name": "...", "label": "...", "type": "..."}],
  "rows": [],
  "chart": None,
  "summary": None,
  "warnings": [],
  "meta": {"generated_at": "...", "source": "sqlbot"}
}
```

- 去除 SQLBot 内部 Token/chat_id 等敏感字段
- 行数超限时截断并设 `truncated: True`

### T09：实现四个工具 Handler (`handlers/`)

每个 handler 返回 JSON 字符串，不抛异常给 Agent Loop：

- **ask.py**：首次查询时自动登录 SQLBot + 创建 chat_id --> session store；通过 `mcp_question` 提问 --> query_guard --> result_guard --> normalizer
- **followup.py**：从 session store 取 chat_id，复用 --> `mcp_question`；无 chat_id 时返回 `QUERY_CONTEXT_NOT_FOUND`
- **explain.py**：返回最近一次查询的 SQL/数据源/筛选信息，不重新查数据库
- **reset.py**：清除 session store 中的 chat_id 映射
