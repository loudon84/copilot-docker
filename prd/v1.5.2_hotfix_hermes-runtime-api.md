# PRD v1.5.2：修复 copilot-docker Hermes Agent API Server 未启动导致 8642 外部不可访问的问题

## 1. 文档信息

版本：v1.5.2
项目：copilot-docker
目标仓库：https://github.com/loudon84/copilot-docker
修复类型：Bug Fix / Runtime API Exposure
影响模块：docker-compose.yml、Dockerfile、启动脚本、create-instance.sh、实例 .env、健康检查、nodeskclaw 接入
目标实例：common-writer 以及后续所有 Hermes profile 实例

## 2. 问题背景

当前 `copilot-docker` 已经可以成功构建镜像并启动实例：

```text
hermes-common-writer
0.0.0.0:8900->8787/tcp
0.0.0.0:28900->8642/tcp
```

其中：

```text
8900 -> 8787 = Hermes WebUI
28900 -> 8642 = 预期的 Hermes Agent API / Gateway 接口
```

但实际在容器内部访问：

```bash
curl -v http://127.0.0.1:8642/
```

返回：

```text
Connection refused
```

说明容器内没有进程监听 `8642`。

当前 Docker 端口映射存在，但容器内 Hermes Agent API Server 没有启动。因此外部访问 `28900` 必然失败。

## 3. Bug 定义

### 3.1 Bug 标题

Hermes Agent API Server 未启用且未随容器启动，导致 `HERMES_GATEWAY_PORT -> 8642` 端口映射不可访问。

### 3.2 Bug 表现

宿主机：

```bash
curl -v http://127.0.0.1:28900/health
```

失败。

容器内：

```bash
curl -v http://127.0.0.1:8642/health
```

失败。

`docker ps` 显示端口映射存在：

```text
0.0.0.0:28900->8642/tcp
```

但容器内没有监听：

```bash
ss -lntp | grep 8642
```

无输出。

### 3.3 根因

当前项目只完成了端口映射：

```text
host HERMES_GATEWAY_PORT -> container 8642
```

但没有完成以下动作：

1. 未在容器环境变量中设置 `API_SERVER_ENABLED=true`
2. 未设置 `API_SERVER_KEY`
3. 未设置 `API_SERVER_HOST=0.0.0.0`
4. 未显式启动 `hermes gateway`，因此 API Server 不会启动
5. healthcheck 只检查 WebUI `8787/health`，没有检查 Hermes Agent API Server
6. `create-instance.sh` 打印了 `Gateway: http://:<port>`，但实际并未保证该接口可用

### 3.4 影响

1. nodeskclaw 无法通过 `HERMES_GATEWAY_PORT` 监听 profile 状态。
2. nodeskclaw 无法通过 Hermes API 调用 profile 的 skills。
3. 多 profile 实例虽然 WebUI 正常，但 Agent API 入口不可用。
4. 用户会误以为 Docker 端口映射、防火墙或 gbrain 导致失败。
5. 当前 `Gateway` 命名和实际服务行为不一致，造成运维误判。

## 4. 产品目标

### 4.1 核心目标

修复后，每个实例应同时启动：

```text
Hermes WebUI       : container 8787 -> host HERMES_WEBUI_PORT
Hermes Agent API   : container 8642 -> host HERMES_GATEWAY_PORT
```

其中 Hermes Agent API Server 必须支持 nodeskclaw 调用：

```text
GET  /health
GET  /v1/models
GET  /v1/capabilities
GET  /v1/skills
GET  /v1/toolsets
POST /v1/chat/completions
POST /v1/runs
GET  /v1/runs/{run_id}
GET  /v1/runs/{run_id}/events
POST /v1/runs/{run_id}/stop
```

### 4.2 非目标

本版本不做：

1. 不自研 `agent_runtime_api.py`
2. 不使用 `hermes dashboard` 替代 Agent API
3. 不修改 Hermes Agent 源码
4. 不修改 Hermes WebUI 前端逻辑
5. 不处理 gbrain MCP 启动失败问题
6. 不改变 WebUI 端口 `8787`
7. 不改变实例目录结构

## 5. 正确技术路线

使用 Hermes 官方 API Server 能力：

```env
API_SERVER_ENABLED=true
API_SERVER_KEY=<token>
API_SERVER_HOST=0.0.0.0
API_SERVER_PORT=8642
API_SERVER_MODEL_NAME=<profile>
```

然后启动：

```bash
hermes gateway
```

或：

```bash
/app/venv/bin/hermes gateway run
```

API Server 启动成功后，应监听：

```text
0.0.0.0:8642
```

宿主机通过 Docker 映射访问：

```text
http://127.0.0.1:${HERMES_GATEWAY_PORT}
```

## 6. 需求范围

## FR-1：docker-compose.yml 注入 API_SERVER_* 环境变量

### 需求描述

当前 `docker-compose.yml` 已经有：

```yaml
ports:
  - "${HERMES_WEBUI_BIND:-0.0.0.0}:${HERMES_WEBUI_PORT:-8787}:8787"
  - "${HERMES_GATEWAY_BIND:-0.0.0.0}:${HERMES_GATEWAY_PORT:-8642}:8642"
```

需要补充 environment：

```yaml
API_SERVER_ENABLED: ${API_SERVER_ENABLED:-true}
API_SERVER_KEY: ${API_SERVER_KEY:?API_SERVER_KEY is required}
API_SERVER_HOST: ${API_SERVER_HOST:-0.0.0.0}
API_SERVER_PORT: ${API_SERVER_PORT:-8642}
API_SERVER_MODEL_NAME: ${API_SERVER_MODEL_NAME:-${HERMES_PROFILE:-hermes-agent}}
API_SERVER_CORS_ORIGINS: ${API_SERVER_CORS_ORIGINS:-}
GATEWAY_ALLOW_ALL_USERS: ${GATEWAY_ALLOW_ALL_USERS:-true}
```

如果 Compose 对嵌套默认值兼容性不好，则使用简单写法：

```yaml
API_SERVER_MODEL_NAME: ${API_SERVER_MODEL_NAME:-hermes-agent}
```

### 验收标准

执行：

```bash
docker exec hermes-common-writer printenv | grep -E 'API_SERVER|GATEWAY_ALLOW'
```

必须输出：

```text
API_SERVER_ENABLED=true
API_SERVER_KEY=***
API_SERVER_HOST=0.0.0.0
API_SERVER_PORT=8642
API_SERVER_MODEL_NAME=common-writer
```

## FR-2：实例 .env 自动生成 API Server 配置

### 需求描述

`create-instance.sh` 当前根据 WebUI 端口生成：

```bash
GATEWAY_PORT=$((20000 + PORT))
```

并打印：

```text
Gateway: http://:$GATEWAY_PORT
```

需要在实例 `.env` 中生成 API Server 配置，保证该 Gateway 端口确实可用。

### 新增 .env 字段

每个实例 `.env` 必须包含：

```env
HERMES_WEBUI_PORT=<webui_port>
HERMES_GATEWAY_PORT=<20000 + webui_port>
HERMES_GATEWAY_BIND=0.0.0.0

API_SERVER_ENABLED=true
API_SERVER_KEY=<auto-generated-token>
API_SERVER_HOST=0.0.0.0
API_SERVER_PORT=8642
API_SERVER_MODEL_NAME=<profile>
API_SERVER_CORS_ORIGINS=

GATEWAY_ALLOW_ALL_USERS=true
```

### API_SERVER_KEY 生成规则

如果用户没有提供，应自动生成强随机 token：

```bash
API_SERVER_KEY="$(openssl rand -base64 48 | tr -d '/+=' | cut -c1-40)"
```

要求：

1. 不得默认使用 `change-me-local-dev`
2. 不得为空
3. 写入 `.env`
4. 文件权限保持 `600`

### create-instance.sh 输出调整

当前输出：

```text
Gateway: http://:<port> (nodeskclaw / 外部 Agent 接入)
```

应改为：

```text
Agent API: http://127.0.0.1:<gateway_port>
Agent API Key: <hidden; see .env>
Health: curl http://127.0.0.1:<gateway_port>/health
Models: curl -H "Authorization: Bearer <API_SERVER_KEY>" http://127.0.0.1:<gateway_port>/v1/models
```

不要直接在终端打印完整 API key，避免泄露。

## FR-3：启动脚本必须同时启动 WebUI 与 Hermes Gateway API Server

### 需求描述

当前 Dockerfile 最终：

```dockerfile
CMD ["/hermeswebui_init.bash"]
```

而 `/hermeswebui_init.bash` 来自 hermes-webui 镜像初始化脚本，主要启动 WebUI。当前没有保证启动 `hermes gateway`。

需要在项目中提供自己的 entrypoint wrapper，例如：

```text
docker/entrypoint.sh
```

由它负责：

1. 初始化目录权限
2. 启动 Hermes Agent API Server
3. 启动 Hermes WebUI
4. 监听子进程状态
5. 任何核心服务异常退出时退出容器

### 新增 docker/entrypoint.sh

建议实现：

```bash
#!/usr/bin/env bash
set -euo pipefail

log() {
  echo "[entrypoint] $*"
}

export HERMES_HOME="${HERMES_HOME:-/data/hermes}"
export HERMES_CONFIG_PATH="${HERMES_CONFIG_PATH:-/data/hermes/config.yaml}"
export API_SERVER_ENABLED="${API_SERVER_ENABLED:-true}"
export API_SERVER_HOST="${API_SERVER_HOST:-0.0.0.0}"
export API_SERVER_PORT="${API_SERVER_PORT:-8642}"

mkdir -p "$HERMES_HOME" "$HERMES_HOME/logs"

log "HERMES_PROFILE=${HERMES_PROFILE:-default}"
log "HERMES_HOME=$HERMES_HOME"
log "HERMES_CONFIG_PATH=$HERMES_CONFIG_PATH"
log "HERMES_WEBUI_PORT=${HERMES_WEBUI_PORT:-8787}"
log "API_SERVER_ENABLED=${API_SERVER_ENABLED}"
log "API_SERVER_HOST=${API_SERVER_HOST}"
log "API_SERVER_PORT=${API_SERVER_PORT}"
log "API_SERVER_MODEL_NAME=${API_SERVER_MODEL_NAME:-}"

if [ "${API_SERVER_ENABLED}" = "true" ] || [ "${API_SERVER_ENABLED}" = "1" ] || [ "${API_SERVER_ENABLED}" = "yes" ]; then
  if [ -z "${API_SERVER_KEY:-}" ]; then
    log "ERROR: API_SERVER_KEY is required when API_SERVER_ENABLED=true"
    exit 1
  fi

  log "Starting Hermes Agent API Server via hermes gateway..."
  /app/venv/bin/hermes gateway run > "$HERMES_HOME/logs/hermes-gateway.log" 2>&1 &
  HERMES_GATEWAY_PID=$!
  log "Hermes gateway pid=$HERMES_GATEWAY_PID"

  for i in $(seq 1 60); do
    if curl -fsS "http://127.0.0.1:${API_SERVER_PORT}/health" >/dev/null 2>&1; then
      log "Hermes Agent API Server is ready on ${API_SERVER_HOST}:${API_SERVER_PORT}"
      break
    fi

    if ! kill -0 "$HERMES_GATEWAY_PID" >/dev/null 2>&1; then
      log "ERROR: Hermes gateway exited during startup"
      tail -200 "$HERMES_HOME/logs/hermes-gateway.log" || true
      exit 1
    fi

    sleep 1
  done

  if ! curl -fsS "http://127.0.0.1:${API_SERVER_PORT}/health" >/dev/null 2>&1; then
    log "ERROR: Hermes Agent API Server did not become ready"
    tail -200 "$HERMES_HOME/logs/hermes-gateway.log" || true
    exit 1
  fi
else
  log "API server disabled; skip hermes gateway startup"
fi

log "Starting Hermes WebUI..."
/hermeswebui_init.bash &
HERMES_WEBUI_PID=$!
log "Hermes WebUI pid=$HERMES_WEBUI_PID"

wait -n "$HERMES_WEBUI_PID" ${HERMES_GATEWAY_PID:-}
EXIT_CODE=$?

log "A core process exited; stopping container. exit=$EXIT_CODE"

if [ -n "${HERMES_GATEWAY_PID:-}" ]; then
  kill "$HERMES_GATEWAY_PID" >/dev/null 2>&1 || true
fi

kill "$HERMES_WEBUI_PID" >/dev/null 2>&1 || true

exit "$EXIT_CODE"
```

### Dockerfile 修改

新增：

```dockerfile
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod 555 /entrypoint.sh
EXPOSE 8787 8642
CMD ["/entrypoint.sh"]
```

替换原来的：

```dockerfile
EXPOSE 8787
CMD ["/hermeswebui_init.bash"]
```

### 验收标准

容器启动后：

```bash
docker exec hermes-common-writer ss -lntp | grep -E '8787|8642'
```

必须同时看到：

```text
0.0.0.0:8787
0.0.0.0:8642
```

或至少：

```text
*:8787
*:8642
```

## FR-4：healthcheck 同时检查 WebUI 与 Agent API

### 需求描述

当前 healthcheck 只检查：

```yaml
curl -fsS http://127.0.0.1:8787/health
```

需要改成同时检查：

```bash
curl -fsS http://127.0.0.1:8787/health
curl -fsS http://127.0.0.1:${API_SERVER_PORT:-8642}/health
```

### docker-compose.yml 修改

建议：

```yaml
healthcheck:
  test:
    [
      "CMD-SHELL",
      "curl -fsS http://127.0.0.1:8787/health >/dev/null && if [ \"${API_SERVER_ENABLED:-true}\" = \"true\" ]; then curl -fsS http://127.0.0.1:${API_SERVER_PORT:-8642}/health >/dev/null; fi"
    ]
  interval: 30s
  timeout: 5s
  retries: 5
  start_period: 90s
```

如果 Compose 变量嵌套在 healthcheck 中兼容性不稳定，可以改为在镜像中新增：

```text
docker/healthcheck.sh
```

内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

curl -fsS http://127.0.0.1:8787/health >/dev/null

if [ "${API_SERVER_ENABLED:-true}" = "true" ]; then
  curl -fsS "http://127.0.0.1:${API_SERVER_PORT:-8642}/health" >/dev/null
fi
```

Dockerfile：

```dockerfile
COPY docker/healthcheck.sh /usr/local/bin/hermes-healthcheck.sh
RUN chmod +x /usr/local/bin/hermes-healthcheck.sh
HEALTHCHECK --interval=30s --timeout=5s --start-period=90s --retries=5 CMD /usr/local/bin/hermes-healthcheck.sh
```

## FR-5：新增 API Server 验证脚本

### 需求描述

新增脚本：

```text
scripts/check-agent-api.sh
```

用于验证某个 profile 的 Agent API 是否可用。

### 脚本用法

```bash
bash scripts/check-agent-api.sh common-writer
```

### 脚本行为

1. 读取 `instances/<profile>/.env`
2. 获取 `HERMES_GATEWAY_PORT`
3. 获取 `API_SERVER_KEY`
4. 检查 `/health`
5. 检查 `/v1/models`
6. 检查 `/v1/capabilities`
7. 检查 `/v1/skills`
8. 输出 nodeskclaw 可使用的连接信息

### 参考实现

```bash
#!/usr/bin/env bash
set -euo pipefail

PROFILE="${1:?usage: check-agent-api.sh <profile>}"
BASE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
ENV_FILE="$BASE_DIR/instances/$PROFILE/.env"

if [ ! -f "$ENV_FILE" ]; then
  echo "ERROR: env file not found: $ENV_FILE" >&2
  exit 1
fi

set -a
. "$ENV_FILE"
set +a

PORT="${HERMES_GATEWAY_PORT:?HERMES_GATEWAY_PORT missing}"
KEY="${API_SERVER_KEY:?API_SERVER_KEY missing}"
BASE_URL="http://127.0.0.1:${PORT}"

echo "[check-agent-api] profile=$PROFILE"
echo "[check-agent-api] base_url=$BASE_URL"

echo "== health =="
curl -fsS "$BASE_URL/health"
echo

echo "== models =="
curl -fsS "$BASE_URL/v1/models" \
  -H "Authorization: Bearer $KEY"
echo

echo "== capabilities =="
curl -fsS "$BASE_URL/v1/capabilities" \
  -H "Authorization: Bearer $KEY"
echo

echo "== skills =="
curl -fsS "$BASE_URL/v1/skills" \
  -H "Authorization: Bearer $KEY"
echo

echo "[check-agent-api] OK"
```

## FR-8：保持 gbrain 失败不阻塞 API Server

### 需求描述

当前 gbrain MCP 连接失败不应阻断 Hermes API Server 启动。

如果 `hermes gateway` 因 gbrain MCP 初始化失败直接退出，需要在本版本增加配置开关：

```env
GBRAIN_ENABLED=0
```

或在 config 生成逻辑中让 gbrain MCP 可选。

### 本版本策略

1. 默认不处理 gbrain 本身问题。
2. 如果 gbrain 启动失败但 Hermes gateway 继续运行，视为可接受。
3. 如果 gbrain 启动失败导致 gateway 退出，则本 PRD 追加一项 hotfix：`create-instance.sh` 支持 `GBRAIN_ENABLED=0` 禁用 gbrain MCP。

## 7. 安全要求

## SR-1：API_SERVER_KEY 必须强制存在

当：

```env
API_SERVER_ENABLED=true
```

但：

```env
API_SERVER_KEY=
```

为空时，entrypoint 必须直接退出。

## SR-2：默认不能使用弱口令

不允许默认：

```env
API_SERVER_KEY=change-me-local-dev
```

仅允许在开发示例文档中出现。

## SR-3：绑定 0.0.0.0 时必须使用 Bearer Token

由于 API Server 能访问 Hermes Agent 完整工具集，包括 terminal、文件、skills、memory，因此对外暴露时必须带认证。

## SR-4：CORS 默认关闭

默认：

```env
API_SERVER_CORS_ORIGINS=
```

只有 nodeskclaw 或浏览器端确实需要跨域访问时，才显式配置来源：

```env
API_SERVER_CORS_ORIGINS=http://127.0.0.1:3000,http://localhost:3000
```

## 14. 风险与规避

### 风险 1：`hermes gateway run` 参数在不同版本有差异

规避：

启动脚本中先检测：

```bash
/app/venv/bin/hermes gateway --help
```

如果 `gateway run` 不可用，则 fallback：

```bash
/app/venv/bin/hermes gateway
```

建议实现函数：

```bash
start_gateway() {
  if /app/venv/bin/hermes gateway run --help >/dev/null 2>&1; then
    /app/venv/bin/hermes gateway run
  else
    /app/venv/bin/hermes gateway
  fi
}
```

### 风险 2：gateway 前台阻塞

规避：

entrypoint 中后台启动 gateway：

```bash
/app/venv/bin/hermes gateway run &
```

再启动 WebUI。

### 风险 3：gateway 启动失败导致容器 unhealthy

规避：

当 `API_SERVER_ENABLED=true` 时，这是正确行为。因为该实例声明需要 Agent API，如果 API 不可用，应 unhealthy。

### 风险 4：API Server 对外暴露安全风险

规避：

1. 强制 `API_SERVER_KEY`
2. 默认不启用 CORS
3. 文档警告不要使用弱 key
4. 推荐内网访问或由 nodeskclaw 反向代理统一鉴权
