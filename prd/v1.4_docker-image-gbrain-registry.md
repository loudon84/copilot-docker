# PRD：copilot-docker 镜像构建、GBrain 安装与 Local Registry 发布治理方案

版本：v1.4_docker-image-gbrain-registry
适用仓库：loudon84/copilot-docker
目标模块：Dockerfile、docker-compose.yml、create-instance.sh、up-instance.sh、build-image.sh、build-push-registry.sh、build-push-local-registry.sh、local-registry.env.example、registry.env.example、doctor-local-registry.sh

---

## 1. 背景

当前 Hermes WebUI + Hermes Agent Docker 镜像已经可以完成基础运行，但在 GBrain 集成、镜像构建验收、本地 Registry 发布方面存在不稳定点。

已确认问题：

1. 容器内手工执行 `git clone http://git.superic.com/aiplatform/gbrain.git /opt/gbrain` 后可以正常安装 GBrain。
2. Dockerfile 中使用 `bun install -g http://git.superic.com/aiplatform/gbrain.git` 会被 Bun 当成 tarball 地址解压，导致 `ZlibError`。
3. Dockerfile 对 GBrain 安装失败使用 `|| echo WARN`，构建不会失败，最终镜像缺少 `gbrain`。
4. Hermes 运行时配置启用了 GBrain MCP，但容器内不存在 `gbrain` 可执行文件，导致启动日志出现：

   ```text
   missing executable 'gbrain'
   ```
5. `up-instance.sh` 默认复用已有镜像，Dockerfile 修复后如果不强制 build，实例仍然使用旧镜像。
6. 本地 Registry 已有脚本链路，但构建参数、版本标签、GBrain 安装验收还需要统一。

---

## 2. 总体目标

### 2.1 功能目标

1. Docker 镜像构建阶段必须稳定安装 GBrain。
2. GBrain 安装失败时，构建必须失败，不能生成“残缺镜像”。
3. 镜像内必须能通过 `/usr/local/bin/gbrain` 直接执行 GBrain。
4. Hermes MCP 配置中 GBrain command 应使用绝对路径：

   ```yaml
   command: /usr/local/bin/gbrain
   ```
5. Dockerfile、docker-compose.yml、build 脚本、registry 脚本中的 GBrain 参数必须统一。
6. Local Registry 支持完整链路：

   ```text
   启动 Registry → 配置 insecure registry → 构建镜像 → 推送 → doctor 校验 → nodeskclaw 使用镜像
   ```
7. 构建完成后必须提供容器内验收命令，确认：

   ```bash
   which gbrain
   gbrain --help
   hermes doctor
   ```

### 2.2 非目标

1. 不在本版本改造 Hermes Agent 内部 GBrain 业务逻辑。
2. 不把 GBrain 源码挂载到实例数据目录。
3. 不把 `/data/hermes/gbrain` 当成 GBrain 可执行文件安装目录。
4. 不让每个实例重复安装 GBrain。GBrain 属于镜像层能力，实例只保存运行数据。

## 3. 当前问题分析

### 3.1 Dockerfile 问题

当前逻辑：

```dockerfile
ARG INSTALL_GBRAIN=1
ARG GBRAIN_REPO=http://git.superic.com/aiplatform/gbrain.git
RUN if [ "${INSTALL_GBRAIN}" = "1" ]; then \
      (curl -fsSL https://bun.sh/install | bash -s -- bun-v1.2.15 \
        && ln -sf /root/.bun/bin/bun /usr/local/bin/bun \
        && ln -sf /root/.bun/bin/bunx /usr/local/bin/bunx \
        && bun install -g "${GBRAIN_REPO}" \
        && echo "OK: gbrain installed") \
      || echo "WARN: gbrain install failed; init-brain-runtime.sh will skip gbrain."; \
    fi
```

问题：

1. `bun install -g "${GBRAIN_REPO}"` 不适用于当前 Git HTTP 地址。
2. 失败后被 `echo WARN` 吞掉。
3. 未固定 `GBRAIN_REF`。
4. 未将 `gbrain` 软链到 `/usr/local/bin/gbrain`。
5. 最后权限段没有处理 `/opt/bun`、`/opt/gbrain`。
6. 构建阶段没有强制执行 `command -v gbrain` 作为验收。

### 4.1 镜像层

镜像内固定目录：

```text

├── skills/
├── skill-inbox/
```

## 5. Dockerfile 修改要求

### 5.1 增加构建参数

在 GBrain 安装段增加：

```dockerfile
ARG INSTALL_GBRAIN=1
ARG GBRAIN_REPO=http://git.superic.com/aiplatform/gbrain.git
ARG GBRAIN_REF=master

ENV BUN_INSTALL=/opt/bun
ENV PATH=/opt/bun/bin:/usr/local/bin:$PATH
```

### 5.2 替换 GBrain 安装逻辑

将原来的 `bun install -g "${GBRAIN_REPO}"` 整段替换为：

```dockerfile
RUN if [ "${INSTALL_GBRAIN}" = "1" ]; then \
      set -eux; \
      \
      echo "== install bun =="; \
      curl -fsSL https://bun.sh/install | bash -s -- bun-v1.2.15; \
      ln -sf /opt/bun/bin/bun /usr/local/bin/bun; \
      ln -sf /opt/bun/bin/bunx /usr/local/bin/bunx; \
      bun --version; \
      \
      echo "== clone gbrain =="; \
      rm -rf /opt/gbrain; \
      git clone --depth=1 --branch "${GBRAIN_REF}" "${GBRAIN_REPO}" /opt/gbrain; \
      test -f /opt/gbrain/package.json; \
      \
      echo "== inspect gbrain package =="; \
      cd /opt/gbrain; \
      cat package.json; \
      \
      echo "== install gbrain from local repo =="; \
      bun install; \
      (bun install -g /opt/gbrain || npm install -g .); \
      \
      echo "== locate gbrain =="; \
      find /opt/bun /root/.bun /home/hermeswebui/.bun /usr/local/bin -type f -name gbrain -print || true; \
      GBRAIN_BIN="$(find /opt/bun /root/.bun /home/hermeswebui/.bun /usr/local/bin -type f -name gbrain 2>/dev/null | head -1)"; \
      test -n "$GBRAIN_BIN"; \
      chmod +x "$GBRAIN_BIN"; \
      ln -sf "$GBRAIN_BIN" /usr/local/bin/gbrain; \
      \
      chmod -R a+rX /opt/bun /opt/gbrain; \
      command -v gbrain; \
      gbrain --help >/tmp/gbrain-help.txt 2>&1 || true; \
      head -80 /tmp/gbrain-help.txt || true; \
      echo "OK: gbrain installed"; \
    else \
      echo "SKIP: INSTALL_GBRAIN=${INSTALL_GBRAIN}"; \
    fi
```

### 5.3 修改权限段

原权限段需要追加：

```text
/opt/bun
/opt/gbrain
```

目标：

```dockerfile
RUN mkdir -p /data/hermes /workspace /uv_cache /app \
  && touch /app/venv/.deps_installed \
  && chown -R hermeswebui:hermeswebui \
      /data \
      /workspace \
      /uv_cache \
      /app \
      /app/venv \
      /home/hermeswebui/.hermes \
      /opt/hermes-agent \
      /opt/bun \
      /opt/gbrain \
  && chmod -R u+rwX,g+rwX \
      /data \
      /workspace \
      /uv_cache \
      /app \
      /app/venv \
      /home/hermeswebui/.hermes \
      /opt/bun \
      /opt/gbrain
```

### 5.4 构建失败原则

GBrain 安装失败时，Docker build 必须失败。

禁止：

```dockerfile
|| echo "WARN: gbrain install failed"
```

允许：

```dockerfile
command -v gbrain
```

作为构建验收。

当前已有：

```yaml

GBRAIN_REPO: ${GBRAIN_REPO:-http://git.superic.com/aiplatform/gbrain.git}
```

需要补充：

```yaml

```

目标：

```yaml
build:
  args:
    HERMES_WEBUI_REPO: ${HERMES_WEBUI_REPO:-http://git.superic.com/aiplatform/hermes-webui.git}
    HERMES_WEBUI_REF: ${HERMES_WEBUI_REF:-master}
    HERMES_AGENT_REPO: ${HERMES_AGENT_REPO:-http://git.superic.com/aiplatform/hermes-agent.git}
    HERMES_AGENT_REF: ${HERMES_AGENT_REF:-master}
    HERMES_VERSION: ${HERMES_VERSION:-git-build}
    INSTALL_GBRAIN: ${INSTALL_GBRAIN:-1}
    GBRAIN_REPO: ${GBRAIN_REPO:-http://git.superic.com/aiplatform/gbrain.git}
    GBRAIN_REF: ${GBRAIN_REF:-master}
    INSTALL_FILESYSTEM_MCP: ${INSTALL_FILESYSTEM_MCP:-1}
    INSTALL_CLAWSEC: ${INSTALL_CLAWSEC:-0}
    CLAWSEC_REPO: ${CLAWSEC_REPO:-http://git.superic.com/aiplatform/clawsec.git}
    USE_CN_MIRRORS: ${USE_CN_MIRRORS:-1}
    APT_MIRROR: ${APT_MIRROR:-https://mirrors.aliyun.com/debian}
    PIP_INDEX_URL: ${PIP_INDEX_URL:-https://mirrors.aliyun.com/pypi/simple/}
    NPM_REGISTRY: ${NPM_REGISTRY:-https://registry.npmmirror.com}
```

### 6.2 environment 保持 GBrain 运行路径

保留：

```yaml
GBRAIN_ENABLED: ${GBRAIN_ENABLED:-1}
GBRAIN_HOME: /data/hermes/gbrain
GBRAIN_VAULT: /data/hermes/obsidian-vault
```

建议补充：

```yaml
GBRAIN_COMMAND: /usr/local/bin/gbrain
```

用于后续 config 模板生成。

### 6.3 端口规划

当前只暴露 WebUI：

```yaml
ports:
  - "${HERMES_WEBUI_BIND:-0.0.0.0}:${HERMES_WEBUI_PORT:-8787}:8787"
```

建议预留 Gateway 端口，但默认不对外开放：

```yaml
# 可选，调试时开启
# - "${HERMES_GATEWAY_BIND:-127.0.0.1}:${HERMES_GATEWAY_PORT:-8642}:8642"
```

`.env` 可加入：

```env
HERMES_GATEWAY_BIND=127.0.0.1
HERMES_GATEWAY_PORT=8642
```

## 10. 新增 scripts/doctor-image.sh

目标：检查镜像是否具备 Hermes/GBrain 基础能力。

用法：

```bash
bash scripts/doctor-image.sh
bash scripts/doctor-image.sh hermes-agent-webui:latest
```

脚本逻辑：

```bash
#!/usr/bin/env bash
set -euo pipefail

IMAGE="${1:-hermes-agent-webui:latest}"

docker run --rm --entrypoint bash "$IMAGE" -lc '
set -e

echo "== python =="
/app/venv/bin/python -V

echo "== hermes-agent import =="
/app/venv/bin/python - <<PY
from run_agent import AIAgent
print("OK: AIAgent importable")
PY

echo "== gbrain =="
which gbrain
gbrain --help 2>&1 | head -80

echo "== filesystem mcp =="
which mcp-server-filesystem || true
which npx || true

echo "OK: image doctor passed"
'
```

验收要求：

```text
which gbrain 必须成功
AIAgent import 必须成功
```

## 17. 配置模板要求：config.yaml

GBrain MCP 配置应固定为：

```yaml
mcp_servers:
  gbrain:
    command: /usr/local/bin/gbrain
    args: []
    enabled: true
```

如果 `GBRAIN_ENABLED=0`，则生成：

```yaml
mcp_servers:
  gbrain:
    command: /usr/local/bin/gbrain
    args: []
    enabled: false
```

不要使用：

```yaml
command: gbrain
```

## 20. 风险与回滚

### 风险 1：GBrain 仓库 package.json 没有 bin 字段

处理：

```bash
cat /opt/gbrain/package.json
```

如果没有 `bin.gbrain`，需要 GBrain 仓库补 package.json。

### 风险 2：bun install -g /opt/gbrain 不生成可执行文件

处理：

```bash
npm install -g .
```

Dockerfile 已使用 fallback：

```bash
(bun install -g /opt/gbrain || npm install -g .)
```

### 风险 3：旧实例仍复用旧镜像

处理：

```bash
bash scripts/up-instance.sh <profile> --build
```

或：

```bash
docker compose --env-file instances/<profile>/.env -p hermes-<profile> build --no-cache
```

### 风险 4：Local Registry pull 失败

处理：

```bash
sudo bash scripts/configure-insecure-registry.sh
sudo systemctl restart docker
bash scripts/doctor-local-registry.sh
```
