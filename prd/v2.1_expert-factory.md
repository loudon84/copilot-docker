# 1. 版本定位

v2.0 已完成 Expert Factory 的基础协议、源码目录、Python CLI、静态校验、基础评测和 Expert Bundle 构建。

v2.1 在 v2.0 基础上完成以下七项正式生产能力：

```text
create-expert
customize-expert
validate-expert
evaluate-expert
build-expert
branch-expert
publish-expert
```

形成完整生产链路：

```text
业务需求
→ Expert Brief
→ Expert Plan
→ Expert Source
→ Branch / Customize
→ Validate
→ Evaluate
→ Build
→ Expert Bundle
→ Publish to Nacos
```

本版本的最终验收目标：

1. 能够从业务需求生成完整 Expert Source；
2. 能够由 Expert Source 构建不可变 Expert Bundle；
3. Bundle 通过协议、安全、权限、依赖和真实运行评测；
4. Bundle 可以发布为 Nacos AgentSpec；
5. Bundle 内 Skill 可以同步发布到 Nacos Skill Registry；
6. 发布过程具有版本、标签、审核、摘要和审计记录。

## 2.2 当前源码需要升级的问题

### 2.2.1 create-expert 仍属于 Scaffold Generator

当前实现只读取结构化 YAML Brief，根据 `required_capabilities` 生成 Skill Stub，根据 `external_systems` 生成 Connector Slot，并生成基础 SOUL、Policy 和两个评测用例。生成的 Skill 内容仍是通用占位结构。

当前尚未完成：

* 从自然语言或完整 PRD 提取需求；
* 搜索现有 Skill、Plugin、Connector，避免重复创建；
* 生成完整 Skill 执行规则；
* 生成场景化评测数据；
* 生成真实团队成员职责；
* 检查组件职责重叠；
* 对专家方案进行风险分析。

---

### 2.2.2 customize-expert 仍属于完整目录复制

当前实现采用 `shutil.copytree` 复制源专家，修改 Expert ID、提升 patch 版本并写入 `derived_from`。尚未对具体变更内容进行结构化表达，也没有判断权限是否扩大。

当前尚未完成：

* 局部 Overlay；
* 文件级和字段级差异；
* 权限增量分析；
* Connector Slot 变更分析；
* Skill 冲突检查；
* 源版本升级同步；
* Rebase 和 Merge；
* Copy-on-Write。

---

### 2.2.3 evaluate-expert 尚不是真实运行评测

当前 Task、Policy、Security 和 Resilience Case 主要通过：

* Prompt 关键词与 Skill 触发词匹配；
* SOUL、Skill 中是否存在“禁止”“密钥”“写入”等文字；
* Connector Slot 是否存在；
* 输出格式声明是否存在。

这些检查能够验证静态语义，但没有实际调用 Hermes Agent，也没有验证最终回复、Tool Call 和权限执行行为。

当前 Runtime Smoke 主要检查：

* SOUL 文件存在；
* Skill 可发现；
* Plugin Python 可编译；
* `plugin.yaml` 存在；
* MCP YAML、JSON 可解析；
* 可选运行实例 API 健康。

它没有在隔离 Hermes Runtime 中执行业务问题。

当前评分器在某个评测维度没有任何检查项时，默认将该维度计为 `1.0`，可能导致缺失能力未被扣分。

---

### 2.2.4 build-expert 尚未达到正式发布级

当前构建器已经实现：

* 完整校验前置；
* release 模式评测 Gate；
* ZIP 固定时间戳；
* 文件 SHA-256；
* Payload Digest；
* evaluation.json；
* source.json；
* Bundle 构建报告。

需要改进：

1. 虽然声明了 `RUNTIME_INCLUDE`，实际打包文件仍由全目录递归扫描和排除列表控制，应改为显式白名单；
2. Evaluation Report 仅按 Expert ID 和版本查找，没有绑定 Source Digest；
3. 同版本源码修改后，可能误用旧评测结果；
4. `source.json` 包含本地绝对路径；
5. `built_at` 进入 Bundle，影响相同源码重复构建结果；
6. 当前 SBOM 主要是文件列表，不是标准依赖 SBOM；
7. 尚未生成 Bundle 签名；
8. 尚未提供独立 Bundle Validator；
9. 尚未验证 ZIP Bomb、重复路径和解压后大小。

现有实现细节可见构建器源码。

---

### 2.2.5 安全扫描范围需要收紧

当前 Secret Scanner 会跳过：

* `docs/`；
* `prd/`；
* `tests/`；
* `scripts/`；
* `config.yaml`。

其中 `scripts/` 和实际运行配置仍可能进入 Bundle，不应整体排除安全扫描。

---

### 2.2.6 CI/CD 尚未完成 Release 和发布链路

当前 GitHub Actions 覆盖：

* 主分支和 Pull Request；
* 全量校验；
* 静态评测；
* 单元测试；
* 主分支 Dev Bundle 构建；
* CI Artifact 上传。

当前 Workflow 没有 Tag 触发、Release Bundle、完整 Runtime Evaluation 或 Nacos Publish Job。

# 3. 产品定位

改造后的 `copilot-docker` 定位为：

> WorkCopilot 专家资产的源码生产、派生定制、分支管理、协议校验、安全检查、运行评测、Bundle 构建和 Registry 发布系统。

正式职责：

```text
Expert Source Production
Expert Source Governance
Expert Evaluation
Expert Bundle Build
Expert Registry Publish
Runtime Image Build
```

不负责：

* 企业用户和组织管理；
* Expert 使用授权；
* Connector 实例绑定；
  -生产 Secret 管理；
  -生产 Expert 实例调度；
  -任务运行；
  -专家运行审计；
  -专家使用统计；
  -Nacos 内部审核页面；
  -nodeskclaw Expert Registry 页面。

上述运行和治理能力由 `nodeskclaw`、Nacos 和 Runtime 层负责。

## 7.5 Skill 类型字段

新建 Skill 必须声明：

```yaml
kind: procedural | general | tool | connector | policy
```

定义：

| kind       | 执行语义          |
| ---------- | ------------- |
| procedural | 确定性 SOP 或业务流程 |
| general    | 开放型专业任务       |
| tool       | 原子执行能力包装      |
| connector  | 外部系统连接方法      |
| policy     | 权限、安全或审核规则    |

旧 Skill 缺少 `kind` 时允许兼容读取，但发布时输出 Warning。

# 10. create-expert

## 10.1 目标

从业务需求、PRD 或 Expert Brief 生成完整可校验 Expert Source。

---

## 10.2 输入类型

```text
自然语言需求
Markdown PRD
YAML Expert Brief
已有 Expert Plan
```

CLI：

```bash
scripts/expert/expert create \
  --requirements docs/requirements/finance-risk.md \
  --output expert-templates/finance-risk
```

已有 Brief：

```bash
scripts/expert/expert create \
  --brief docs/briefs/finance-risk.yaml \
  --output expert-templates/finance-risk
```

仅生成方案：

```bash
scripts/expert/expert create \
  --requirements docs/requirements/finance-risk.md \
  --plan-only
```

---

## 10.3 执行流程

```text
Requirement Intake
→ Brief Compilation
→ Existing Component Discovery
→ Component Planning
→ Risk Planning
→ Source Generation
→ Initial Validation
```

---

## 10.4 Existing Component Discovery

创建前必须扫描：

```text
expert-templates/*/skills
expert-templates/*/plugins
expert-templates/*/tools
expert-factory/templates
Nacos Skill Registry（可选）
```

输出：

```yaml
reusable_components:
  - type: skill
    id: receivable-aging-analysis
    source: expert-templates/finance/skills/receivable-aging-analysis
    decision: reuse

new_components:
  - type: skill
    id: collection-risk-review
    reason: 当前仓库无对应能力
```

禁止默认重复生成同职责 Skill 或 Plugin。

---

## 10.5 Expert Plan

必须包含：

* 业务目标；
* 角色边界；
* 输入；
* 输出；
* Skill；
* SOP；
* Tool；
* Plugin；
* Connector Slot；
  -权限；
  -模型能力要求；
  -评测场景；
  -不支持范围；
  -复用决策；
  -风险；
  -不创建组件及原因。

---

## 10.6 Source Generation

生成内容必须达到可运行草稿标准，不再只生成通用 Skill Stub。

每个 Skill 至少包含：

* 明确触发条件；
* 输入契约；
* 输出契约；
* 工具调用规则；
* Connector 使用规则；
* 错误处理；
* 权限边界；
* 禁止事项；
* 两个正常用例；
* 一个异常用例；
* 一个安全用例。

---

## 10.7 验收

* 可从 Markdown PRD 生成 Brief；
* 可生成 Expert Plan；
* 可识别复用组件；
* 生成至少一个完整 Skill；
* 生成权限策略；
* 生成评测集；
* 生成 Connector Slot；
* 通过 structure 和 schema 校验；
* 不生成 Secret；
* 不修改现有 Expert。

# 12. branch-expert

## 12.1 目标

实现 Expert 模板的 Copy-on-Write 分支机制，解决公共模板升级和部门定制冲突。

这里的 Branch 是 Expert Asset Branch，不是 Git Branch。

---

## 12.2 分支结构

```text
.workcopilot/branches/<expert-id>/<branch-id>/
├── branch.yaml
├── overlay/
│   ├── skills/
│   ├── policies/
│   └── docs/
├── deleted-files.yaml
└── reports/
    ├── diff.json
    ├── diff.md
    └── conflict-report.md
```

分支只保存变更文件，不复制完整源专家。

---

## 12.3 子命令

### 创建分支

```bash
scripts/expert/expert branch create \
  expert-templates/finance-risk \
  --name corp-finance \
  --target-id corp-finance-risk
```

### 查看状态

```bash
scripts/expert/expert branch status \
  .workcopilot/branches/finance-risk/corp-finance
```

### 查看差异

```bash
scripts/expert/expert branch diff \
  .workcopilot/branches/finance-risk/corp-finance
```

### Rebase

```bash
scripts/expert/expert branch rebase \
  .workcopilot/branches/finance-risk/corp-finance \
  --onto expert-templates/finance-risk
```

### 物化为 Expert Source

```bash
scripts/expert/expert branch materialize \
  .workcopilot/branches/finance-risk/corp-finance \
  --output expert-templates/corp-finance-risk
```

---

## 12.4 状态规则

### synced

```text
base_digest == current source digest
且 overlay 不与源更新冲突
```

### behind

```text
源 Expert 已更新
分支尚未 Rebase
```

### diverged

```text
分支存在私有改动
但可自动合并
```

### conflicted

```text
源和分支修改了同一 YAML 字段或同一文本区域
```

### materialized

```text
已生成独立 Expert Source
```

---

## 12.5 合并规则

YAML 文件采用字段级三方合并。

Markdown 文件采用：

```text
base
source-head
branch-head
```

三方文本合并。

以下内容发生冲突时禁止自动解决：

* Tool 权限；
* Connector access_mode；
  -数据分类；
  -导出权限；
  -Required Gate；
  -发布状态；
  -Secret 配置。

---

## 12.6 验收

* 分支创建不复制完整目录；
* 分支记录 Source Digest；
* 可识别 synced、behind、diverged 和 conflicted；
* 可生成差异报告；
* 可 Rebase；
* 可物化为完整 Expert Source；
* 冲突未解决前禁止 build 和 publish。

# 14. evaluate-expert

## 14.1 目标

将当前静态语义检查升级为真实 Expert 行为评测。

---

## 14.2 评测模式

### static

执行：

* Schema；
  -Skill 触发；
  -权限；
  -Connector；
  -输出契约；
  -依赖；
  -静态安全；
  -文档完整度。

### runtime

在隔离 Hermes Runtime 中执行实际 Case。

### full

```text

+ security adversarial
+ resilience

```

---

## 14.3 Hermes Runtime Harness

每次评测创建独立运行目录：

```text
.workcopilot/cache/evaluations/<run-id>/
├── hermes-home/
├── workspace/
├── fixtures/
├── artifacts/
├── events/
└── logs/
```

执行流程：

```text
创建临时 HERMES_HOME
→ 注入 Expert Source 或 Bundle
→ 注入测试模型配置
→ 启动 Hermes Gateway
→ 注入 Mock Connector
→ 执行 Case
→ 采集最终回复和 Tool Calls
→ 停止 Gateway
→ 删除临时 Secret
```

禁止修改：

```text
instances/
用户 ~/.hermes
生产 Connector
生产数据库
```

```text
mock-finance-query
mock-erp-read
mock-erp-write-denied
mock-email
mock-search
mock-github
mock-timeout
mock-invalid-response
```

Fixture 必须记录：

-输入；
-输出；
-调用次数；
-调用顺序；
-是否发生禁止操作。

# 16. publish-expert

## 16.1 目标

将 Release Expert Bundle 发布到 Nacos AI Registry。

Nacos 3.x 已将 Skill、AgentSpec、Prompt、MCP Server 等纳入 AI Registry，并提供版本、标签、可见性和生命周期能力。

v2.1 最低支持版本：

```text
Nacos >= 3.2.2
```

理由：

* AgentSpec 上传和生命周期接口从 3.2.0 提供；
  -单 Skill ZIP 上传从 3.2.2 提供；
  -批量 Skill ZIP 上传从 3.2.2 提供。

---

## 16.2 发布语义

`Expert Bundle 发布到 Nacos` 定义为：

1. Expert Bundle 是 WorkCopilot 的权威发布产物；
2. `publish-expert` 将 Bundle 转换为 Nacos AgentSpec Package；
3. Bundle 中的 Skills 转换为 Nacos Skill Package；
4. AgentSpec 和 Skills 上传到 Nacos；
5. Nacos 保存版本、状态、标签和可下载包；
6. AgentSpec 扩展字段保存 WorkCopilot Bundle Digest；
7. Publish Record 保存 WorkCopilot 与 Nacos 资源映射。

不将 `.expert.bundle` 作为普通 Config Base64 内容写入 Nacos Configuration Center。

---

## 16.3 Nacos 资源映射

### Expert

```text
WorkCopilot Expert
→ Nacos AgentSpec
```

| WorkCopilot                 | Nacos                 |
| --------------------------- | --------------------- |

| metadata.version            | version               |
| metadata.description        | description           |
| metadata.tags               | bizTags               |
| release.registry.visibility | scope                 |
| release.registry.labels     | labels                |
| Expert Bundle               | AgentSpec ZIP Package |
| Bundle Digest               | AgentSpec extension   |
| Connector Slots             | AgentSpec extension   |
| Runtime Compatibility       | AgentSpec extension   |
| Evaluation Summary          | AgentSpec extension   |

---

### Skill

```text
WorkCopilot Skill
→ Nacos Skill
```

每个 Skill 独立上传和版本化。

Nacos Skill 生命周期为：

```text
upload / editing
→ review / reviewing
→ reviewed
→ release / online
```

官方 CLI 和服务器均采用该生命周期。

## 16.9 幂等和冲突

### 相同 ID、版本和 Digest

```text

```

### Draft 同名冲突

只有显式指定：

```text
--overwrite-draft
```

才能覆盖 Draft。

### Online 发布

禁止使用：

```text
--force
```

---

## 16.10 事务补偿

Nacos 发布涉及多个 Skill 和一个 AgentSpec，不属于单数据库事务。

失败处理：

```text
Skill 上传失败
→ 不上传 AgentSpec

部分 Skill 上传成功
→ 写入 partial Publish Record
→ 允许 resume

AgentSpec 上传失败
→ 保留 Skill Draft
→ 不提交审核

Submit 失败
→ 保留 Draft
→ 不删除资源

Publish 失败
→ 保留 reviewed 状态
→ 允许重试 Publish
```

CLI 支持：

```bash
scripts/expert/expert publish resume \
  .workcopilot/publish/<publish-id>/publish-record.json
```

## 16.11 发布验收

* Release Bundle 可生成 Nacos AgentSpec Package；
  -所有 Skill 可上传到 Skill Registry；
  -AgentSpec 可上传；
  -AgentSpec 与 Skill 可提交审核；
  -reviewed 版本可发布 online；
  -可更新 latest 标签；
  -可设置 PRIVATE 或 PUBLIC；
  -相同摘要重复发布不产生重复版本；
  -不同摘要同版本发布被阻断；
  -发布结果可回读；
  -生成 Publish Record；
  -发布日志不包含账号和 Token。
