# PRD：copilot-docker 支持本地 Docker Registry 镜像构建与推送

版本号：copilot_docker_v1.1_local-registry
关联项目：team_v3.0_agent-expert
目标仓库：https://github.com/loudon84/copilot-docker
目标用途：为 nodeskclaw CE 的 `hermes-webui-expert` runtime 提供本地镜像仓库测试链路。

## 1. 背景

当前 `copilot-docker` 已具备 Hermes WebUI + Hermes Agent 专家服务镜像构建能力，并已有 `build-push-registry.sh` 用于推送到远程镜像仓库。

但在公司暂未开通火山、阿里云、Harbor 等正式镜像仓库前，需要先用本地 Docker Registry 验证以下链路：

```text
copilot-docker 构建 hermes-webui-expert 镜像
  ↓
推送到本地 Docker Registry
  ↓
nodeskclaw 配置本地镜像仓库
  ↓
nodeskclaw 发布引擎版本
  ↓
nodeskclaw 拉取镜像并部署 Hermes 专家员工
```

## 2. 核心目标

新增一套本地 Registry 测试脚本与文档，使开发人员可以在 `192.168.102.247:9900` 这类内网地址上完成镜像构建、推送、验证和 nodeskclaw 配置。

## 3. 现状分析

### 3.1 当前已有能力

仓库已有：

```text

```

其中：

* `registry.env.example` 用于配置远程镜像仓库。

* `create-instance.sh` 用于本地创建 writer/finance 实例目录。
* `up-instance.sh` 用于本地启动实例容器。


## 4. 设计原则

### 4.1 本地 Registry 仅用于测试

本地 Registry 用于开发、联调、POC，不作为正式生产镜像仓库。

### 4.2 nodeskclaw 只拉取镜像

本地 Registry 方案中，nodeskclaw 仍然只负责：

```text
配置镜像仓库
读取 tag
发布引擎版本
部署专家员工
```

不在 nodeskclaw 内执行镜像构建。

### 4.3 构建和运行数据分离

镜像只包含 Hermes WebUI、Hermes Agent 和运行依赖。

不得把以下实例数据固化进镜像：

```text
WebUI 密码
Hindsight bank_id
sessions
workspace 运行文件
memories 运行数据
实例级 config
```

这些仍由 nodeskclaw 或专家模板注入生成。

## 5. 需要新增的文件

### 5.1 新增 `local-registry.env.example`

路径：

```text
local-registry.env.example
```

内容目标：

```env
LOCAL_REGISTRY_HOST=192.168.102.247
LOCAL_REGISTRY_PORT=9900
LOCAL_REGISTRY_CONTAINER_NAME=local-registry
LOCAL_REGISTRY_DATA_DIR=/data/docker-registry

IMAGE_REPO=192.168.102.247:9900/hermes-webui-expert
IMAGE_TAG=v2026.6.1

HERMES_WEBUI_REPO=http://git.superic.com/aiplatform/hermes-webui.git
HERMES_WEBUI_REF=master
HERMES_AGENT_REPO=http://git.superic.com/aiplatform/hermes-agent.git
HERMES_AGENT_REF=master

INSTALL_GBRAIN=1
GBRAIN_REPO=http://git.superic.com/aiplatform/gbrain.git
INSTALL_FILESYSTEM_MCP=1
INSTALL_CLAWSEC=0
CLAWSEC_REPO=http://git.superic.com/aiplatform/clawsec.git

BUILD_PLATFORM=linux/amd64
```

### 5.2 新增 `scripts/start-local-registry.sh`

职责：

```text
1. 读取 local-registry.env。
2. 创建 registry 数据目录。
3. 启动 registry:2 容器。
4. 默认使用宿主机 9900 → 容器 5000。
5. 如果已存在 local-registry，则提示当前状态。
```

核心命令：

```bash
docker run -d \
  --name local-registry \
  --restart=always \
  -p 9900:5000 \
  -v /data/docker-registry:/var/lib/registry \
  registry:2
```

### 5.3 新增 `scripts/stop-local-registry.sh`

职责：

```text
停止并删除本地 registry 容器。
默认不删除 /data/docker-registry 数据。
```

支持参数：

```text
--remove-data    同时删除 registry 数据目录
```

### 5.4 新增 `scripts/configure-insecure-registry.sh`

职责：

```text
1. 把 192.168.102.247:9900 写入 /etc/docker/daemon.json 的 insecure-registries。
2. 如果 daemon.json 已存在，则合并配置，不覆盖已有配置。
3. 重启 docker。
4. 输出当前 docker info 中的 Insecure Registries。
```

注意：

```text
需要 sudo 权限。
需要在所有需要 push/pull 的 Docker 主机上执行。
```

### 5.5 新增 `scripts/build-push-local-registry.sh`

职责：

```text
1. 读取 local-registry.env。
2. 检查 Docker、buildx、registry 可访问性。
3. 构建 hermes-webui-expert 镜像。
4. 优先采用 --load 构建到本地 Docker daemon。
5. 使用 docker push 推送到 HTTP insecure local registry。
6. 验证 registry tags list。
7. 输出 nodeskclaw 配置建议。
```

为什么采用 `--load + docker push`：

```text
HTTP 本地 registry 属于 insecure registry。
docker buildx --push 在 docker-container builder 下可能无法读取宿主机 Docker daemon 的 insecure registry 配置。
使用 --load 后再 docker push，兼容性更高。
```

核心构建命令：

```bash
docker buildx build \
  --platform linux/amd64 \
  -t "${IMAGE_REPO}:${IMAGE_TAG}" \
  --build-arg HERMES_WEBUI_REPO="${HERMES_WEBUI_REPO}" \
  --build-arg HERMES_WEBUI_REF="${HERMES_WEBUI_REF}" \
  --build-arg HERMES_AGENT_REPO="${HERMES_AGENT_REPO}" \
  --build-arg HERMES_AGENT_REF="${HERMES_AGENT_REF}" \
  --build-arg HERMES_VERSION="${IMAGE_TAG}" \
  --build-arg INSTALL_GBRAIN="${INSTALL_GBRAIN}" \
  --build-arg GBRAIN_REPO="${GBRAIN_REPO}" \
  --build-arg INSTALL_FILESYSTEM_MCP="${INSTALL_FILESYSTEM_MCP}" \
  --build-arg INSTALL_CLAWSEC="${INSTALL_CLAWSEC}" \
  --build-arg CLAWSEC_REPO="${CLAWSEC_REPO}" \
  --load \
  .
```

然后：

```bash
docker push "${IMAGE_REPO}:${IMAGE_TAG}"
```

### 5.6 新增 `scripts/doctor-local-registry.sh`

职责：

```text
1. 检查 registry 容器状态。
2. 检查 /v2/_catalog。
3. 检查 hermes-webui-expert tags。
4. 检查本机 docker daemon insecure registry 配置。
5. 检查镜像是否可以 pull。
```


## 8. 验收标准

### 8.1 本地 Registry 验收

```text
1. docker ps 能看到 local-registry。
2. curl http://192.168.102.247:9900/v2/_catalog 返回 JSON。
3. curl http://192.168.102.247:9900/v2/hermes-webui-expert/tags/list 返回 v2026.6.1。
```

### 8.2 镜像构建验收

```text
1. docker images 能看到 192.168.102.247:9900/hermes-webui-expert:v2026.6.1。
2. docker push 成功。
3. docker pull 成功。
```

### 8.3 nodeskclaw 验收

```text
1. nodeskclaw 镜像仓库配置为 192.168.102.247:9900/hermes-webui-expert。
2. 用户名、密码为空。
3. 引擎版本发布 v2026.6.1。
4. 创建 Hermes 专家员工时可以拉取该镜像。
5. 专家员工容器启动成功。
6. WebUI 可访问。
```

## 9. 常见错误

### 9.1 `http: server gave HTTP response to HTTPS client`

原因：

```text
Docker 默认按 HTTPS 访问 registry，但本地 registry 是 HTTP。
```

处理：

```text
在所有需要 push/pull 的 Docker 主机上配置 insecure-registries。
```

### 9.2 `connection refused`

原因：

```text
registry 容器未启动
端口映射错误
防火墙未放行 9900
```

处理：

```text
确认使用 -p 9900:5000
确认 docker ps
确认 curl http://192.168.102.247:9900/v2/_catalog
```

### 9.3 `no basic auth credentials`

原因：

```text
命令误用了需要认证的远程 registry，或 IMAGE_REPO 配错。
```

处理：

```text
确认 IMAGE_REPO=192.168.102.247:9900/hermes-webui-expert
本地 registry 测试模式不需要 docker login
```

### 9.4 buildx push 失败

原因：

```text
buildx docker-container builder 可能无法继承宿主机 insecure registry 配置。
```

处理：

```text
使用 --load 构建到本地，再 docker push。
```
