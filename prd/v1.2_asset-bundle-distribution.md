# PRD：Hermes Agent 实例能力包导出、导入与复用

版本：`copilot-docker_v1.2_asset-bundle-distribution`

仓库：`loudon84/copilot-docker`

## 1. 背景

当前 `copilot-docker` 用于部署多个 Hermes Agent WebUI 实例。每个实例按 profile 独立保存运行数据：

```text
instances/<profile>/data/hermes/
```

现有实例如 `writer`、`finance` 在长期使用后，会产生或安装一批可复用能力：

```text
skills/
tools/
plugins/
mcp/
policies/
skill-bundles/
gbrain/
```

这些能力需要快速复制给新同事的新实例，例如：

```text
hermes-writer -> hermes-writer2
hermes-finance -> hermes-finance-user-a
```

当前做法依赖手工 `docker cp`，存在以下问题：

1. 路径不统一，部分工具放在 `/opt/hermes-agent/tools`，部分放在 `~/.hermes/tools`。
2. `/opt/hermes-agent` 属于镜像层，容器重建后手工复制内容会丢失。
3. Python 依赖没有随工具一起安装。
4. 无法清晰区分“可复用能力”和“个人数据/密钥/记忆”。
5. 新建实例后不能自动继承成熟实例的 skills、tools、plugins。

本版本目标是把这些能力沉淀成标准资产包，支持导出、导入、查看、模板化复用。

---

## 2. 目标

### 2.1 产品目标

实现一套标准机制：

```text
成熟 Hermes 实例
    -> 导出 Asset Bundle
    -> 保存到 asset-bundles/
    -> 导入新实例
    -> 自动安装依赖
    -> 重启后可直接使用
```

支持后续沉淀到专家模板：

```text
Asset Bundle
    -> expert-templates/writer
    -> expert-templates/finance
    -> 新建实例自动继承
```

### 2.2 技术目标

1. 标准化实例级能力目录。
2. 将 `tools`、`plugins` 纳入实例持久化目录。
3. 通过 volume 映射兼容 Hermes 默认查找路径。
4. 新增导出脚本。
5. 新增导入脚本。
6. 新增查看脚本。
7. 新增将 bundle 固化到 expert template 的脚本。
8. 新增文档说明使用规则。
9. 避免复制 secrets、memory、sessions、logs、workspace 等个人数据。
10. Python 依赖统一安装到 `/app/venv`。

---

## 3. 非目标

本版本不做以下内容：

1. 不修改 Hermes Agent 源码。
2. 不实现 WebUI 页面管理 asset bundle。
3. 不实现远程 bundle registry。
4. 不自动同步 Hindsight 记忆库。
5. 不复制个人 workspace 文件。
6. 不复制 session、webui state、logs。
7. 不复制实例 `.env`、`config.yaml` 中的密钥。
8. 不自动处理 apt/system 级依赖。
9. 不修改 nodeskclaw 后端逻辑。
10. 不做多机器分发。

## 4. 目录规范

### 4.1 实例持久化目录

所有可复制的运行期能力统一放入：

```text
instances/<profile>/data/hermes/
├── skills/
├── tools/
├── plugins/
├── mcp/
├── policies/
├── skill-bundles/
└── gbrain/
```

### 4.2 Hermes 兼容路径

容器内兼容 Hermes 默认路径：

```text
/home/hermeswebui/.hermes/tools
/home/hermeswebui/.hermes/plugins
```

这两个路径必须映射到实例持久化目录：

```text
/data/hermes/tools
/data/hermes/plugins
```

### 4.3 镜像内置路径

以下路径属于镜像层：

```text
/opt/hermes-agent
/home/hermeswebui/.hermes/hermes-agent
```

规则：

1. 不建议通过 asset bundle 修改 `/opt/hermes-agent`。
2. 通用源码级工具应在 Dockerfile 中固化。
3. 实例级工具应放在 `/data/hermes/tools`。
4. 若历史工具存在于 `/opt/hermes-agent/tools`，导出时可以迁移到 bundle 的 `tools/`，导入后落到 `/data/hermes/tools`。

## 6. docker-compose.yml 修改要求

### 6.1 增加 tools/plugins volume

在 `services.hermes-agent-webui.volumes` 下增加：

```yaml
volumes:
  - ./instances/${HERMES_PROFILE:-default}/data/hermes:/data/hermes
  - ./instances/${HERMES_PROFILE:-default}/data/hermes/tools:/home/hermeswebui/.hermes/tools
  - ./instances/${HERMES_PROFILE:-default}/data/hermes/plugins:/home/hermeswebui/.hermes/plugins
```

### 6.2 增加环境变量

在 `environment` 下增加：

```yaml
HERMES_TOOLS_PATH: /data/hermes/tools
HERMES_PLUGINS_PATH: /data/hermes/plugins
```

保留已有：

```yaml
HERMES_SKILLS_PATH: /data/hermes/skills
HERMES_WORKSPACE_PATH: /data/hermes/workspace
```

### 6.3 用户权限保持

保留：

```yaml
user: "1000:1000"
```

容器内运行用户必须是 UID 1000 / GID 1000。

## 10. 新增脚本：scripts/export-assets.sh

### 10.1 用法

```bash
bash scripts/export-assets.sh <source_profile> <bundle_name>
```

示例：

```bash
bash scripts/export-assets.sh writer writer-search-v1
bash scripts/export-assets.sh finance finance-report-v1
```

### 10.2 功能

从运行中的实例容器导出可复用资产：

```text
/data/hermes/skills
/data/hermes/tools
/data/hermes/plugins
/data/hermes/mcp
/data/hermes/policies
/data/hermes/skill-bundles
/data/hermes/gbrain
```

如果历史工具存在于以下路径，也要复制到临时目录后导出：

```text
/home/hermeswebui/.hermes/tools
/home/hermeswebui/.hermes/plugins
/opt/hermes-agent/tools
/opt/hermes-agent/plugins
```

导出目标：

```text
asset-bundles/<bundle_name>/data-hermes-assets.tgz
```

同时生成：

```text
asset-bundles/<bundle_name>/manifest.json
asset-bundles/<bundle_name>/pip-freeze.txt
asset-bundles/<bundle_name>/requirements.txt
asset-bundles/<bundle_name>/npm-global.txt
asset-bundles/<bundle_name>/apt-packages.txt
asset-bundles/<bundle_name>/README.md
asset-bundles/<bundle_name>/verify.sh
```

### 10.3 导出规则

允许导出：

```text
skills/
tools/
plugins/
mcp/
policies/
skill-bundles/
gbrain/
```

禁止导出：

```text
.env
config.yaml
memories/
sessions/
logs/
webui/
workspace/
obsidian-vault/
hindsight/
backups/
```

### 10.4 requirements.txt 规则

脚本自动生成 `pip-freeze.txt`：

```bash
/app/venv/bin/python -m pip freeze > pip-freeze.txt
```

但 `requirements.txt` 默认只生成空文件和注释，不直接等于 `pip-freeze.txt`。

原因：

1. `pip-freeze.txt` 是完整环境快照。
2. `requirements.txt` 是 bundle 最小依赖。
3. 最小依赖应人工确认后写入。

默认内容：

```txt
# Add minimum Python dependencies required by this bundle.
# Do not paste full pip-freeze unless the bundle really needs it.
```

### 10.5 export-assets.sh 参考实现

```bash
#!/usr/bin/env bash
set -euo pipefail

PROFILE="${1:?usage: export-assets.sh <source_profile> <bundle_name>}"
BUNDLE="${2:?usage: export-assets.sh <source_profile> <bundle_name>}"

BASE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
CONTAINER="hermes-$PROFILE"
OUT_DIR="$BASE_DIR/asset-bundles/$BUNDLE"
TMP_DIR="/tmp/hermes-asset-export-$BUNDLE"

docker inspect "$CONTAINER" >/dev/null 2>&1 || {
  echo "ERROR: container not found: $CONTAINER"
  exit 1
}

rm -rf "$OUT_DIR"
mkdir -p "$OUT_DIR"

docker exec "$CONTAINER" bash -lc "
set -e
rm -rf '$TMP_DIR'
mkdir -p '$TMP_DIR'

for d in skills tools plugins mcp policies skill-bundles gbrain; do
  if [ -d /data/hermes/\$d ]; then
    mkdir -p '$TMP_DIR'
    cp -a /data/hermes/\$d '$TMP_DIR/' || true
  fi
done

if [ -d /home/hermeswebui/.hermes/tools ]; then
  mkdir -p '$TMP_DIR/tools'
  cp -a /home/hermeswebui/.hermes/tools/. '$TMP_DIR/tools/' || true
fi

if [ -d /home/hermeswebui/.hermes/plugins ]; then
  mkdir -p '$TMP_DIR/plugins'
  cp -a /home/hermeswebui/.hermes/plugins/. '$TMP_DIR/plugins/' || true
fi

if [ -d /opt/hermes-agent/tools ]; then
  mkdir -p '$TMP_DIR/tools'
  cp -a /opt/hermes-agent/tools/. '$TMP_DIR/tools/' || true
fi

if [ -d /opt/hermes-agent/plugins ]; then
  mkdir -p '$TMP_DIR/plugins'
  cp -a /opt/hermes-agent/plugins/. '$TMP_DIR/plugins/' || true
fi

cd '$TMP_DIR'
tar czf /tmp/data-hermes-assets.tgz .
"

docker cp "$CONTAINER:/tmp/data-hermes-assets.tgz" "$OUT_DIR/data-hermes-assets.tgz"

docker exec "$CONTAINER" bash -lc "/app/venv/bin/python -m pip freeze" > "$OUT_DIR/pip-freeze.txt" || true

cat > "$OUT_DIR/requirements.txt" <<'EOF'
# Add minimum Python dependencies required by this bundle.
# Do not paste full pip-freeze unless the bundle really needs it.
EOF

cat > "$OUT_DIR/npm-global.txt" <<'EOF'
# Add npm global packages required by this bundle, one per line.
EOF

cat > "$OUT_DIR/apt-packages.txt" <<'EOF'
# Add apt packages required by this bundle.
# These are not installed automatically by import-assets.sh.
# Put system packages into Dockerfile for production images.
EOF

cat > "$OUT_DIR/verify.sh" <<'EOF'
#!/usr/bin/env bash
set -euo pipefail

echo "== verify bundle paths =="
ls -la /data/hermes/skills 2>/dev/null || true
ls -la /data/hermes/tools 2>/dev/null || true
ls -la /data/hermes/plugins 2>/dev/null || true
ls -la /data/hermes/mcp 2>/dev/null || true

echo "== python =="
/app/venv/bin/python - <<'PY'
print("python ok")
PY
EOF
chmod +x "$OUT_DIR/verify.sh"

cat > "$OUT_DIR/manifest.json" <<EOF
{
  "schema_version": "1.0",
  "bundle": "$BUNDLE",
  "source_profile": "$PROFILE",
  "source_container": "$CONTAINER",
  "asset_archive": "data-hermes-assets.tgz",
  "python_deps_file": "requirements.txt",
  "npm_deps_file": "npm-global.txt",
  "apt_deps_file": "apt-packages.txt",
  "exported_at": "$(date -Iseconds)",
  "include": [
    "skills",
    "tools",
    "plugins",
    "mcp",
    "policies",
    "skill-bundles",
    "gbrain"
  ],
  "exclude": [
    ".env",
    "config.yaml",
    "memories",
    "sessions",
    "logs",
    "webui",
    "workspace",
    "obsidian-vault",
    "hindsight",
    "backups"
  ],
  "notes": "Do not include secrets, personal memory, sessions, logs, workspace files, or Hindsight bank config."
}
EOF

cat > "$OUT_DIR/README.md" <<EOF
# $BUNDLE

Source profile: $PROFILE  
Source container: $CONTAINER

## Import

\`\`\`bash
bash scripts/import-assets.sh <target_profile> $BUNDLE --restart
\`\`\`

## Verify

\`\`\`bash
docker exec -it hermes-<target_profile> bash /tmp/verify.sh
\`\`\`
EOF

echo "OK: exported bundle to $OUT_DIR"
```

## 11. 新增脚本：scripts/import-assets.sh

### 11.1 用法

```bash
bash scripts/import-assets.sh <target_profile> <bundle_name> [--restart]
```

示例：

```bash
bash scripts/import-assets.sh writer2 writer-search-v1 --restart
bash scripts/import-assets.sh finance-user-a finance-report-v1 --restart
```

### 11.2 功能

1. 解压 bundle 到目标实例：

```text
instances/<target_profile>/data/hermes/
```

2. 确保目录存在：

```text
skills/
tools/
plugins/
mcp/
policies/
skill-bundles/
gbrain/
```

3. 修正权限：

```text
1000:1000
```

4. 如果目标容器正在运行：

   * 确保 `~/.hermes/tools` 指向 `/data/hermes/tools`
   * 确保 `~/.hermes/plugins` 指向 `/data/hermes/plugins`
   * 安装 `requirements.txt`
   * 安装 `npm-global.txt`
   * 拷贝 `verify.sh`
   * 可选重启容器

5. 不修改 `.env`。

6. 不修改 `config.yaml`。

7. 不修改 memories/sessions/workspace/hindsight。

### 11.3 import-assets.sh 参考实现

```bash
#!/usr/bin/env bash
set -euo pipefail

PROFILE="${1:?usage: import-assets.sh <target_profile> <bundle_name> [--restart]}"
BUNDLE="${2:?usage: import-assets.sh <target_profile> <bundle_name> [--restart]}"
RESTART="${3:-}"

BASE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
BUNDLE_DIR="$BASE_DIR/asset-bundles/$BUNDLE"
TARGET_DIR="$BASE_DIR/instances/$PROFILE/data/hermes"
CONTAINER="hermes-$PROFILE"

[ -d "$BUNDLE_DIR" ] || { echo "ERROR: bundle not found: $BUNDLE_DIR"; exit 1; }
[ -f "$BUNDLE_DIR/data-hermes-assets.tgz" ] || { echo "ERROR: missing archive: $BUNDLE_DIR/data-hermes-assets.tgz"; exit 1; }
[ -d "$TARGET_DIR" ] || { echo "ERROR: target instance data dir not found: $TARGET_DIR"; exit 1; }

mkdir -p \
  "$TARGET_DIR/skills" \
  "$TARGET_DIR/tools" \
  "$TARGET_DIR/plugins" \
  "$TARGET_DIR/mcp" \
  "$TARGET_DIR/policies" \
  "$TARGET_DIR/skill-bundles" \
  "$TARGET_DIR/gbrain" \
  "$TARGET_DIR/.backup"

TS="$(date +%Y%m%d-%H%M%S)"
BACKUP_DIR="$TARGET_DIR/.backup/import-$BUNDLE-$TS"
mkdir -p "$BACKUP_DIR"

for d in skills tools plugins mcp policies skill-bundles gbrain; do
  if [ -d "$TARGET_DIR/$d" ]; then
    cp -a "$TARGET_DIR/$d" "$BACKUP_DIR/$d" || true
  fi
done

tar xzf "$BUNDLE_DIR/data-hermes-assets.tgz" -C "$TARGET_DIR"

chown -R 1000:1000 \
  "$TARGET_DIR/skills" \
  "$TARGET_DIR/tools" \
  "$TARGET_DIR/plugins" \
  "$TARGET_DIR/mcp" \
  "$TARGET_DIR/policies" \
  "$TARGET_DIR/skill-bundles" \
  "$TARGET_DIR/gbrain" 2>/dev/null || true

chmod -R u+rwX,g+rwX \
  "$TARGET_DIR/skills" \
  "$TARGET_DIR/tools" \
  "$TARGET_DIR/plugins" \
  "$TARGET_DIR/mcp" \
  "$TARGET_DIR/policies" \
  "$TARGET_DIR/skill-bundles" \
  "$TARGET_DIR/gbrain" 2>/dev/null || true

if docker inspect "$CONTAINER" >/dev/null 2>&1; then
  docker exec -u root "$CONTAINER" bash -lc '
    mkdir -p /data/hermes/tools /data/hermes/plugins /home/hermeswebui/.hermes

    if [ ! -L /home/hermeswebui/.hermes/tools ]; then
      rm -rf /home/hermeswebui/.hermes/tools
      ln -sfn /data/hermes/tools /home/hermeswebui/.hermes/tools
    fi

    if [ ! -L /home/hermeswebui/.hermes/plugins ]; then
      rm -rf /home/hermeswebui/.hermes/plugins
      ln -sfn /data/hermes/plugins /home/hermeswebui/.hermes/plugins
    fi

    chown -R 1000:1000 /data/hermes /home/hermeswebui/.hermes || true
    chmod -R u+rwX,g+rwX /data/hermes /home/hermeswebui/.hermes || true
  '

  if [ -s "$BUNDLE_DIR/requirements.txt" ]; then
    docker cp "$BUNDLE_DIR/requirements.txt" "$CONTAINER:/tmp/hermes-bundle-requirements.txt"
    docker exec -u root "$CONTAINER" bash -lc '
      /app/venv/bin/python -m pip install -r /tmp/hermes-bundle-requirements.txt
      chown -R 1000:1000 /app/venv
    '
  fi

  if [ -s "$BUNDLE_DIR/npm-global.txt" ]; then
    docker cp "$BUNDLE_DIR/npm-global.txt" "$CONTAINER:/tmp/hermes-bundle-npm-global.txt"
    docker exec -u root "$CONTAINER" bash -lc '
      while IFS= read -r pkg; do
        case "$pkg" in
          ""|\#*) continue ;;
          *) npm install -g "$pkg" ;;
        esac
      done < /tmp/hermes-bundle-npm-global.txt
    '
  fi

  if [ -f "$BUNDLE_DIR/verify.sh" ]; then
    docker cp "$BUNDLE_DIR/verify.sh" "$CONTAINER:/tmp/hermes-bundle-verify.sh"
    docker exec -u root "$CONTAINER" bash -lc 'chmod +x /tmp/hermes-bundle-verify.sh'
  fi

  if [ "$RESTART" = "--restart" ]; then
    docker restart "$CONTAINER"
  fi
fi

echo "OK: imported bundle '$BUNDLE' into profile '$PROFILE'"
echo "Backup: $BACKUP_DIR"
```

#!/usr/bin/env bash

将成熟 bundle 固化到专家模板：

```text
asset-bundles/<bundle_name>/data-hermes-assets.tgz
    -> expert-templates/<expert>/
```

以后新建该专家实例时，通过 `inject-expert.sh` 自动注入。

### 13.3 规则

1. 只解压允许复制的目录。
2. 不覆盖 `config.yaml`。
3. 不覆盖 `SOUL.md`，除非 bundle 明确包含。
4. 默认备份原 template 目录。
5. 解压后保留目录结构：

```text
expert-templates/writer/
├── skills/
├── tools/
├── plugins/
├── mcp/
├── policies/
├── skill-bundles/
└── gbrain/
```

### 13.4 参考实现

```bash
#!/usr/bin/env bash
set -euo pipefail

BUNDLE="${1:?usage: promote-bundle-to-template.sh <bundle_name> <expert>}"
EXPERT="${2:?usage: promote-bundle-to-template.sh <bundle_name> <expert>}"

BASE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
BUNDLE_DIR="$BASE_DIR/asset-bundles/$BUNDLE"
TPL_DIR="$BASE_DIR/expert-templates/$EXPERT"

[ -d "$BUNDLE_DIR" ] || { echo "ERROR: bundle not found: $BUNDLE_DIR"; exit 1; }
[ -f "$BUNDLE_DIR/data-hermes-assets.tgz" ] || { echo "ERROR: missing archive: $BUNDLE_DIR/data-hermes-assets.tgz"; exit 1; }
[ -d "$TPL_DIR" ] || { echo "ERROR: expert template not found: $TPL_DIR"; exit 1; }

TS="$(date +%Y%m%d-%H%M%S)"
BACKUP_DIR="$BASE_DIR/expert-templates/.backup/$EXPERT-$TS"
mkdir -p "$(dirname "$BACKUP_DIR")"
cp -a "$TPL_DIR" "$BACKUP_DIR"

tar xzf "$BUNDLE_DIR/data-hermes-assets.tgz" -C "$TPL_DIR"

echo "OK: promoted bundle '$BUNDLE' to expert template '$EXPERT'"
echo "Backup: $BACKUP_DIR"
```

## 16. 依赖处理规范

### 16.1 Python 依赖

所有 Python 依赖安装到：

```text
/app/venv
```

安装命令：

```bash
/app/venv/bin/python -m pip install -r requirements.txt
```

不得使用：

```bash
pip install ...
python -m pip install ...
```

除非明确指向 `/app/venv/bin/python`。

### 16.2 Node 依赖

`npm-global.txt` 中每行一个 npm 包：

```txt
@modelcontextprotocol/server-filesystem
```

安装命令：

```bash
npm install -g <package>
```

### 16.3 apt/system 依赖

`apt-packages.txt` 只做记录，不由 `import-assets.sh` 自动安装。

原因：

1. apt 安装会改变容器系统层。
2. 容器重建后丢失。
3. 生产环境应通过 Dockerfile 固化。

如果 bundle 依赖 apt 包，需要改 Dockerfile 并重新 build。
