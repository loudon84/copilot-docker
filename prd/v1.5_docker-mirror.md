# PRD v1.5：copilot-docker 镜像构建加速与国内镜像源稳定化方案

## 1. 文档信息

版本：v1.5
项目：copilot-docker
目标仓库：https://github.com/loudon84/copilot-docker
目标对象：Dockerfile、docker-compose.yml、实例环境配置、构建脚本
核心目标：解决 Docker image 重构时 apt 下载长期访问 `http://deb.debian.org/debian`，导致构建速度慢、频繁失败的问题。

## 2. 背景

当前项目用于构建 Hermes WebUI + Hermes Agent + GBrain + MCP runtime 的一体化 Docker 镜像。仓库已在 `docker-compose.yml` 中提供以下构建参数：

```env
USE_CN_MIRRORS=1
APT_MIRROR=https://mirrors.aliyun.com/debian
PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
NPM_REGISTRY=https://registry.npmmirror.com
```

但在实际执行 image 重构时，构建日志仍大量出现：

```text
http://deb.debian.org/debian trixie/main ...
Unable to connect to deb.debian.org
```

说明当前国内镜像源参数没有完整作用到 apt 安装阶段。

## 3. 当前问题分析

### 3.1 APT_MIRROR 只传入 compose，但 Dockerfile 没有完整消费

`docker-compose.yml` 已经将 `APT_MIRROR` 作为 build args 传入 Dockerfile，但 Dockerfile 的多阶段构建中，真正大量安装系统包的是 `hermes-webui-base` stage。

当前问题是：

```dockerfile
FROM python:3.12-slim AS hermes-webui-base

ARG BUILD_APT_PROXY=

RUN if [ "A${BUILD_APT_PROXY:-}" != "A" ]; then ...
 && apt-get update
 && apt-get install ...
```

该 stage 没有重新声明：

```dockerfile
ARG USE_CN_MIRRORS
ARG APT_MIRROR
```

也没有在 `apt-get update` 之前替换 `/etc/apt/sources.list.d/debian.sources`。

因此 `APT_MIRROR` 虽然传入了 build args，但未真正改变 apt 源。

### 3.2 Dockerfile 多 stage 的 ARG 作用域导致参数失效

Dockerfile 中 `ARG` 不会自动跨 stage 使用。每个 `FROM` 之后，如果需要使用某个 build arg，必须在该 stage 内重新声明。

因此即使 Stage 1 声明了：

```dockerfile
ARG APT_MIRROR=https://mirrors.aliyun.com/debian
```

Stage 2 仍然不能直接使用。

### 3.3 PIP_INDEX_URL 和 NPM_REGISTRY 不影响 apt 下载

当前失败发生在：

```bash
apt-get install nodejs npm ...
```

这一步是 Debian apt 包下载，不受 pip 源和 npm registry 影响。

`PIP_INDEX_URL` 只影响 pip / uv。
`NPM_REGISTRY` 只影响 `npm install`。
安装 `nodejs npm` 仍然依赖 apt 源。

### 3.4 `python:3.12-slim` 当前可能指向 Debian trixie

构建日志中出现：

```text
trixie/main amd64
```

说明当前基础镜像是 Debian trixie 系。`python:3.12-slim` 是浮动 tag，后续可能随着上游变化改变 Debian 基础版本，影响可重复构建。

## 4. 产品目标

### 4.1 核心目标

1. Docker image 构建时，apt 源必须可配置。
2. 当 `USE_CN_MIRRORS=1` 时，apt 必须使用 `APT_MIRROR`。
3. pip / uv 必须使用 `PIP_INDEX_URL`。
4. npm / npx 必须使用 `NPM_REGISTRY`。
5. 构建日志必须能明确输出当前实际使用的 apt、pip、npm 源。
6. 保持海外环境可关闭国内镜像源。
7. 保持现有 Hermes WebUI + Hermes Agent + GBrain + MCP runtime 功能不变。

### 4.2 非目标

本版本不处理以下事项：

1. 不重构 Hermes WebUI 业务代码。
2. 不改变 Hermes Agent 的 profile、skills、plugins 运行机制。
3. 不引入新的镜像仓库服务。
4. 不处理 Docker Hub 拉取慢的问题。Docker Hub 镜像加速属于 Docker daemon 配置，不属于本 PRD 范围。
5. 不改变容器运行端口、数据卷、Hindsight、GBrain、MCP 配置。

## 6. 功能需求

## FR-1：Dockerfile 支持每个 stage 独立启用 apt 国内镜像

### 需求描述

Dockerfile 中所有执行 `apt-get update` 的 stage，都必须：

1. 重新声明 `ARG USE_CN_MIRRORS`
2. 重新声明 `ARG APT_MIRROR`
3. 在 `apt-get update` 前替换 Debian apt source
4. 输出实际 apt source，便于构建日志排查

### 实施要求

Stage 1：`webui-clone`

需要在 `apt-get update` 前执行换源。

Stage 2：`hermes-webui-base`

需要在 `apt-get update` 前执行换源。

Stage 3：当前不执行 apt 安装，暂不强制换源。但如果后续新增 apt 安装，也必须复用相同换源逻辑。

### 建议实现

新增文件：

```text
docker/apt-mirror.sh
```

内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

USE_CN_MIRRORS="${USE_CN_MIRRORS:-1}"
APT_MIRROR="${APT_MIRROR:-https://mirrors.aliyun.com/debian}"

echo "[apt-mirror] USE_CN_MIRRORS=${USE_CN_MIRRORS}"
echo "[apt-mirror] APT_MIRROR=${APT_MIRROR}"

if [ "${USE_CN_MIRRORS}" != "1" ]; then
  echo "[apt-mirror] CN mirrors disabled. Keep default Debian sources."
  exit 0
fi

if [ -f /etc/apt/sources.list.d/debian.sources ]; then
  sed -i "s|http://deb.debian.org/debian|${APT_MIRROR}|g" /etc/apt/sources.list.d/debian.sources || true
  sed -i "s|https://deb.debian.org/debian|${APT_MIRROR}|g" /etc/apt/sources.list.d/debian.sources || true
fi

if [ -f /etc/apt/sources.list ]; then
  sed -i "s|http://deb.debian.org/debian|${APT_MIRROR}|g" /etc/apt/sources.list || true
  sed -i "s|https://deb.debian.org/debian|${APT_MIRROR}|g" /etc/apt/sources.list || true
fi

echo "[apt-mirror] Effective apt sources:"
grep -R "URIs:\|deb.debian.org\|mirrors." /etc/apt/sources.list /etc/apt/sources.list.d 2>/dev/null || true
```

Dockerfile 中复制并调用：

```dockerfile
COPY docker/apt-mirror.sh /usr/local/bin/apt-mirror.sh
RUN chmod +x /usr/local/bin/apt-mirror.sh
```

但注意：Stage 1 在 clone webui 之前还无法从 repo 内 COPY 文件，如果 `docker/apt-mirror.sh` 位于 build context，仍然可以 COPY。

Stage 1 示例：

```dockerfile
FROM python:3.12-slim AS webui-clone

ARG HERMES_WEBUI_REPO
ARG HERMES_WEBUI_REF
ARG USE_CN_MIRRORS=1
ARG APT_MIRROR=https://mirrors.aliyun.com/debian
ARG PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
ARG NPM_REGISTRY=https://registry.npmmirror.com

ENV USE_CN_MIRRORS=${USE_CN_MIRRORS}
ENV APT_MIRROR=${APT_MIRROR}
ENV PIP_INDEX_URL=${PIP_INDEX_URL}
ENV PIP_TRUSTED_HOST=mirrors.aliyun.com
ENV NPM_CONFIG_REGISTRY=${NPM_REGISTRY}
ENV UV_DEFAULT_INDEX=${PIP_INDEX_URL}

COPY docker/apt-mirror.sh /usr/local/bin/apt-mirror.sh

RUN chmod +x /usr/local/bin/apt-mirror.sh \
 && /usr/local/bin/apt-mirror.sh \
 && apt-get update \
 && apt-get install -y --no-install-recommends git ca-certificates \
 && rm -rf /var/lib/apt/lists/* \
 && git clone --depth=1 --branch "${HERMES_WEBUI_REF}" "${HERMES_WEBUI_REPO}" /src
```

Stage 2 示例：

```dockerfile
FROM python:3.12-slim AS hermes-webui-base

ENV DEBIAN_FRONTEND=noninteractive

ARG BUILD_APT_PROXY=
ARG USE_CN_MIRRORS=1
ARG APT_MIRROR=https://mirrors.aliyun.com/debian
ARG PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
ARG NPM_REGISTRY=https://registry.npmmirror.com

ENV USE_CN_MIRRORS=${USE_CN_MIRRORS}
ENV APT_MIRROR=${APT_MIRROR}
ENV PIP_INDEX_URL=${PIP_INDEX_URL}
ENV PIP_TRUSTED_HOST=mirrors.aliyun.com
ENV UV_DEFAULT_INDEX=${PIP_INDEX_URL}
ENV NPM_CONFIG_REGISTRY=${NPM_REGISTRY}

COPY docker/apt-mirror.sh /usr/local/bin/apt-mirror.sh

RUN chmod +x /usr/local/bin/apt-mirror.sh \
 && if [ "A${BUILD_APT_PROXY:-}" != "A" ]; then \
      printf 'Acquire::http::Proxy "%s";\n' "$BUILD_APT_PROXY" > /etc/apt/apt.conf.d/01proxy; \
    fi \
 && /usr/local/bin/apt-mirror.sh \
 && apt-get update \
 && apt-get install -y --no-install-recommends \
      ca-certificates wget gnupg \
      apt-utils locales sudo curl rsync openssh-client \
      build-essential python3-dev libffi-dev \
      git jq \
      nodejs npm ripgrep ffmpeg procps xz-utils unzip \
 && rm -rf /var/lib/apt/lists/* \
 && apt-get clean
```

## FR-2：docker-compose.yml 增加 BUILD_APT_PROXY 传参

### 需求描述

当前 Dockerfile 已支持 `BUILD_APT_PROXY`，但 compose build args 中未显式传递。需要在 `docker-compose.yml` 中补充：

```yaml
BUILD_APT_PROXY: ${BUILD_APT_PROXY:-}
```

### 目标

当用户处于代理网络环境时，可以在 `.env` 中配置：

```env
BUILD_APT_PROXY=http://host.docker.internal:7890
```

或者：

```env
BUILD_APT_PROXY=http://192.168.1.10:7890
```

使 apt 构建阶段走代理。

## FR-4：build-image.sh 支持构建镜像源参数显示

### 需求描述

执行：

```bash
bash scripts/build-image.sh common-writer
```

或现有构建命令时，脚本需要输出当前构建参数：

```text
[build-image] PROFILE=common-writer
[build-image] ENV_FILE=instances/common-writer/.env
[build-image] USE_CN_MIRRORS=1
[build-image] APT_MIRROR=https://mirrors.aliyun.com/debian
[build-image] PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
[build-image] NPM_REGISTRY=https://registry.npmmirror.com
[build-image] BUILD_APT_PROXY=
```

### 构建命令建议

默认构建不使用 `--pull --no-cache`：

```bash
docker compose --env-file "$ENV_FILE" \
  -p hermes-image-build \
  build --progress=plain
```

提供可选参数：

```bash
bash scripts/build-image.sh common-writer --no-cache
bash scripts/build-image.sh common-writer --pull
bash scripts/build-image.sh common-writer --pull --no-cache
```

脚本内部根据参数拼接：

```bash
BUILD_FLAGS=(--progress=plain)

if [ "$NO_CACHE" = "1" ]; then
  BUILD_FLAGS+=(--no-cache)
fi

if [ "$PULL" = "1" ]; then
  BUILD_FLAGS+=(--pull)
fi
```

## FR-5：增加镜像源验证脚本

### 需求描述

新增：

```text
docker/verify-mirrors.sh
```

容器构建完成后可用于检查：

1. apt sources 是否还有 `deb.debian.org`
2. pip 是否使用指定 index
3. npm 是否使用指定 registry
4. uv 是否使用指定 index

建议内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "== APT sources =="
grep -R "URIs:\|deb.debian.org\|mirrors." /etc/apt/sources.list /etc/apt/sources.list.d 2>/dev/null || true

echo "== pip config =="
python -m pip config list || true
echo "PIP_INDEX_URL=${PIP_INDEX_URL:-}"

echo "== uv config =="
echo "UV_DEFAULT_INDEX=${UV_DEFAULT_INDEX:-}"

echo "== npm config =="
npm config get registry || true
echo "NPM_CONFIG_REGISTRY=${NPM_CONFIG_REGISTRY:-}"
```

Dockerfile 中加入：

```dockerfile
COPY docker/verify-mirrors.sh /usr/local/bin/verify-mirrors.sh
RUN chmod +x /usr/local/bin/verify-mirrors.sh
```

可在构建后测试：

```bash
docker run --rm hermes-agent-webui:latest /usr/local/bin/verify-mirrors.sh
```

## FR-6：基础镜像版本可配置

### 需求描述

当前使用：

```dockerfile
FROM python:3.12-slim
```

建议改为 build arg 可配置：

```dockerfile
ARG PYTHON_BASE_IMAGE=python:3.12-slim-bookworm
FROM ${PYTHON_BASE_IMAGE} AS webui-clone
```

但 Dockerfile 多 stage 中需要在每个 `FROM` 前可用。

### 推荐方案

在 Dockerfile 顶部增加：

```dockerfile
ARG PYTHON_BASE_IMAGE=python:3.12-slim-bookworm
```

然后：

```dockerfile
FROM ${PYTHON_BASE_IMAGE} AS webui-clone
...
FROM ${PYTHON_BASE_IMAGE} AS hermes-webui-base
```

docker-compose.yml 增加：

```yaml
PYTHON_BASE_IMAGE: ${PYTHON_BASE_IMAGE:-python:3.12-slim-bookworm}
```

实例 `.env` 增加：

```env
PYTHON_BASE_IMAGE=python:3.12-slim-bookworm
```

### 说明

默认建议使用 `python:3.12-slim-bookworm`，降低 trixie 包变动导致的不稳定。

如需继续使用 trixie，可在 `.env` 中设置：

```env
PYTHON_BASE_IMAGE=python:3.12-slim-trixie
```

## FR-7：npm 全局安装 MCP 时必须使用 NPM_REGISTRY

### 需求描述

当前 Stage 3 中有：

```dockerfile
RUN if [ "${INSTALL_FILESYSTEM_MCP}" = "1" ]; then \
  npm install -g @modelcontextprotocol/server-filesystem \
  || echo "WARN: filesystem MCP global install failed; npx fallback may still work."; \
fi
```

需要确保此处使用 `NPM_CONFIG_REGISTRY`。

### 实施要求

Stage 3 需要重新声明：

```dockerfile
ARG NPM_REGISTRY=https://registry.npmmirror.com
ENV NPM_CONFIG_REGISTRY=${NPM_REGISTRY}
```

并在安装前输出：

```dockerfile
RUN npm config get registry
```

## FR-8：pip / uv 安装 Hermes Agent 时必须使用 PIP_INDEX_URL

### 需求描述

Stage 3 中执行：

```dockerfile
/app/venv/bin/python -m pip install -e ".[all]"
```

需要确保使用国内 pip 源。

### 实施要求

Stage 3 需要重新声明：

```dockerfile
ARG PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
ENV PIP_INDEX_URL=${PIP_INDEX_URL}
ENV PIP_TRUSTED_HOST=mirrors.aliyun.com
ENV UV_DEFAULT_INDEX=${PIP_INDEX_URL}
```

在 pip 安装前输出：

```dockerfile
RUN echo "PIP_INDEX_URL=${PIP_INDEX_URL}" \
 && echo "UV_DEFAULT_INDEX=${UV_DEFAULT_INDEX}"
```

## 9. 验收标准

## AC-1：APT 源替换成功

执行构建后，日志中必须出现：

```text
[apt-mirror] APT_MIRROR=https://mirrors.aliyun.com/debian
```

且 `apt-get update` 阶段不应继续大量访问：

```text
http://deb.debian.org/debian
```

允许 security 源保留官方源，前提是不影响构建。如果 security 源也失败，需要在后续版本单独扩展 `APT_SECURITY_MIRROR`。

## AC-2：Stage 2 apt 安装不再访问 deb.debian.org 主源

`hermes-webui-base` stage 中的以下系统包安装必须从配置后的 mirror 下载：

```text
nodejs npm git jq ripgrep ffmpeg procps unzip build-essential python3-dev
```

## AC-3：pip 使用 PIP_INDEX_URL

构建 Hermes Agent 依赖时，日志中必须出现：

```text
PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/
```

## AC-4：npm 使用 NPM_REGISTRY

安装 MCP filesystem server 时，日志中必须出现：

```text
https://registry.npmmirror.com
```

## AC-5：关闭国内镜像后可恢复默认源

设置：

```env
USE_CN_MIRRORS=0
```

重新构建时，日志应显示：

```text
[apt-mirror] CN mirrors disabled. Keep default Debian sources.
```

## AC-6：现有运行逻辑不变

构建完成后，以下命令仍然正常：

```bash
bash scripts/up-instance.sh common-writer
```

WebUI 健康检查正常：

## 10.4 scripts/build-image.sh

脚本目标：

1. 支持指定 profile。
2. 自动读取 `instances/<profile>/.env`。
3. 输出镜像源参数。
4. 支持 `--pull` 和 `--no-cache`。

参考实现：

```bash
#!/usr/bin/env bash
set -euo pipefail

PROFILE="${1:-common-writer}"
shift || true

ENV_FILE="instances/${PROFILE}/.env"

if [ ! -f "$ENV_FILE" ]; then
  echo "[build-image] ERROR: env file not found: $ENV_FILE" >&2
  exit 1
fi

NO_CACHE=0
PULL=0

for arg in "$@"; do
  case "$arg" in
    --no-cache) NO_CACHE=1 ;;
    --pull) PULL=1 ;;
    *)
      echo "[build-image] ERROR: unknown arg: $arg" >&2
      exit 1
      ;;
  esac
done

set -a
. "$ENV_FILE"
set +a

echo "[build-image] PROFILE=${PROFILE}"
echo "[build-image] ENV_FILE=${ENV_FILE}"
echo "[build-image] PYTHON_BASE_IMAGE=${PYTHON_BASE_IMAGE:-python:3.12-slim-bookworm}"
echo "[build-image] USE_CN_MIRRORS=${USE_CN_MIRRORS:-1}"
echo "[build-image] APT_MIRROR=${APT_MIRROR:-https://mirrors.aliyun.com/debian}"
echo "[build-image] PIP_INDEX_URL=${PIP_INDEX_URL:-https://mirrors.aliyun.com/pypi/simple/}"
echo "[build-image] NPM_REGISTRY=${NPM_REGISTRY:-https://registry.npmmirror.com}"
echo "[build-image] BUILD_APT_PROXY=${BUILD_APT_PROXY:-}"

BUILD_FLAGS=(--progress=plain)

if [ "$NO_CACHE" = "1" ]; then
  BUILD_FLAGS+=(--no-cache)
fi

if [ "$PULL" = "1" ]; then
  BUILD_FLAGS+=(--pull)
fi

docker compose --env-file "$ENV_FILE" \
  -p hermes-image-build \
  build "${BUILD_FLAGS[@]}"
```

## 12. 风险与规避

## 12.1 Aliyun mirror 对 trixie 支持不稳定

风险：如果继续使用 `python:3.12-slim`，实际可能是 trixie，部分 mirror 同步延迟会导致包下载失败。

规避：默认改为：

```env
PYTHON_BASE_IMAGE=python:3.12-slim-bookworm
```

## 12.2 security 源未替换导致仍访问官方源

风险：`debian.sources` 中 security 源可能仍访问官方。

规避：v1.5 默认只处理主 Debian 源。如果仍失败，v1.5.1 增加：

```env
APT_SECURITY_MIRROR=https://mirrors.aliyun.com/debian-security
```

并单独替换 security source。

## 12.3 `--pull` 仍然慢

风险：`--pull` 拉取基础镜像，与 apt mirror 无关。

规避：文档明确说明：Docker Hub 慢需要配置 Docker daemon 镜像加速，不属于本 PRD 范围。

## 12.4 `.env` 变量含特殊字符

风险：`BUILD_APT_PROXY` 中含特殊字符可能导致 shell 解析问题。

规避：脚本中使用引号包裹变量，并建议用户用普通 HTTP proxy URL。
