# PRD：copilot-docker v1.4.1_hotfix

## Docker 镜像 GBrain 安装修复、共享 Image 构建与实例重建方案

版本：v1.4.1_hotfix
适用仓库：loudon84/copilot-docker
目标范围：Dockerfile、docker-compose.yml、create-instance.sh、up-instance.sh、build-image.sh、Local Registry 发布脚本、镜像验收脚本
优先级：P0
状态：待 Cursor / Coding Agent 实施

---

## 1. 背景

当前 Hermes WebUI + Hermes Agent Docker 镜像在集成 GBrain 时出现构建失败或运行缺失问题。

已确认现象：

```text
docker run --rm --entrypoint bash hermes-agent-webui:latest -lc '
which gbrain
gbrain --help 2>&1 | head -40
'
```

返回：

```text
bash: line 3: gbrain: command not found
```

Docker build 中出现：

```text
Blocked 1 postinstall. Run `bun pm -g untrusted` for details.
Saved lockfile
== locate gbrain ==
find: '/root/.bun': No such file or directory
find: '/home/hermeswebui/.bun': No such file or directory
GBRAIN_BIN=
test -n
```

同时已经确认，在容器内部手工执行：

```bash
git clone http://git.superic.com/aiplatform/gbrain.git /opt/gbrain
cd /opt/gbrain
```

可以正常下载和安装。

因此可以排除：

```text
Git 仓库不可访问
容器网络不可用
基础系统缺少 git
```

当前失败点集中在 Dockerfile 内的 GBrain 安装方式。

---

## 2. 问题定义

### 2.1 当前 Dockerfile 的错误模式

当前 Dockerfile 使用了类似逻辑：

```dockerfile
curl -fsSL https://bun.sh/install | bash -s -- bun-v1.2.15
ln -sf /root/.bun/bin/bun /usr/local/bin/bun
ln -sf /root/.bun/bin/bunx /usr/local/bin/bunx
bun install -g "${GBRAIN_REPO}"
```

当 `GBRAIN_REPO` 为：

```text
http://git.superic.com/aiplatform/gbrain.git
```

时，Bun 没有稳定按 Git 仓库安装，曾出现 tarball 解压错误；改成本地目录安装后，又遇到：

```text
Blocked 1 postinstall
```

导致未生成：

```text
/opt/bun/bin/gbrain
/usr/local/bin/gbrain
```

### 2.2 旧方案的核心缺陷

1. `bun install -g <git-url>` 对当前 Git HTTP 仓库不可靠。
2. `bun install -g /opt/gbrain` 仍可能因为 Bun 的 postinstall 限制不生成 `gbrain` bin。
3. Dockerfile 使用 `GBRAIN_BIN="$(find ... -name gbrain)"` 查找结果为空时构建失败。
4. 旧构建失败后不会更新 `hermes-agent-webui:latest`，用户再 `docker run hermes-agent-webui:latest` 实际运行的是旧镜像。
5. 只用 `docker restart` 不会让已有容器使用新镜像，必须 `force-recreate`。
6. 多实例部署时，如果每个实例都执行 `--build`，会重复构建，浪费时间。
7. 当前没有独立 `doctor-image.sh` 在镜像层验收 `gbrain` 是否存在。

---

## 3. 修复目标

### 3.1 镜像构建目标

Docker build 完成后，镜像内必须满足：

```bash
which bun
bun --version
which gbrain
gbrain --help 2>&1 | head -80
```

其中：

```text
which gbrain
```

必须输出：

```text
/usr/local/bin/gbrain
```

### 3.2 运行目标

Hermes 容器启动后不再出现：

```text
missing executable 'gbrain'
```

Hermes MCP 配置中的 GBrain command 应固定为：

```yaml
command: /usr/local/bin/gbrain
```

### 3.3 多实例目标

镜像只构建一次：

```text
hermes-agent-webui:latest
```

所有实例复用同一个镜像。

更新镜像后，所有实例通过：

```bash
docker compose up -d --no-build --force-recreate
```

重新创建容器，而不是每个实例重新 build。

### 3.4 Local Registry 目标

本地 Registry 发布时，推送的是已经通过 `doctor-image.sh` 验收的镜像。

---

## 4. 非目标

本 hotfix 不做以下事项：

1. 不改 Hermes Agent 内部 GBrain 协议。
2. 不改 GBrain 源码。
3. 不让每个实例单独安装 GBrain。
4. 不把 `/data/hermes/gbrain` 当成可执行文件目录。
5. 不把 GBrain 安装到实例数据目录。
6. 不继续使用 `bun install -g <git-url>` 作为安装方式。

---

## 5. 目录边界

### 5.1 镜像层目录

```text
/opt/hermes-agent       Hermes Agent 源码
/opt/gbrain             GBrain 源码
/opt/bun                Bun 安装目录
/usr/local/bin/bun      Bun 全局入口
/usr/local/bin/bunx     Bunx 全局入口
/usr/local/bin/gbrain   GBrain 全局入口
/app/venv               Python venv
```

### 5.2 实例数据目录

```text
/data/hermes/gbrain             GBrain 运行数据
/data/hermes/obsidian-vault     Vault 数据
/data/hermes/skills             已安装 skills
/data/hermes/skill-inbox        待安装 skills
/data/hermes/tools              Hermes tools
/data/hermes/plugins            Hermes plugins
/data/hermes/webui              WebUI 状态
/data/hermes/workspace          工作区
```

注意：

```text
/opt/gbrain 是源码安装目录
/data/hermes/gbrain 是运行数据目录
/usr/local/bin/gbrain 是执行入口
```

三者不能混用。

## 6. Dockerfile 修改方案

### 6.1 新增安装脚本

新增文件：

```text
docker/install-gbrain.sh
```

内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

INSTALL_GBRAIN="${INSTALL_GBRAIN:-1}"
GBRAIN_REPO="${GBRAIN_REPO:-http://git.superic.com/aiplatform/gbrain.git}"
GBRAIN_REF="${GBRAIN_REF:-master}"
BUN_VERSION="${BUN_VERSION:-bun-v1.2.15}"

if [ "$INSTALL_GBRAIN" != "1" ]; then
  echo "SKIP: INSTALL_GBRAIN=$INSTALL_GBRAIN"
  exit 0
fi

export BUN_INSTALL="${BUN_INSTALL:-/opt/bun}"
export PATH="$BUN_INSTALL/bin:/usr/local/bin:$PATH"

echo "== install bun =="
mkdir -p "$BUN_INSTALL"

if ! command -v bun >/dev/null 2>&1; then
  curl -fsSL https://bun.sh/install | bash -s -- "$BUN_VERSION"
fi

BUN_BIN="$(find "$BUN_INSTALL" /root/.bun /home/hermeswebui/.bun -type f -name bun 2>/dev/null | head -1 || true)"
test -n "$BUN_BIN"
chmod +x "$BUN_BIN"
ln -sf "$BUN_BIN" /usr/local/bin/bun

BUNX_BIN="$(find "$BUN_INSTALL" /root/.bun /home/hermeswebui/.bun -type f -name bunx 2>/dev/null | head -1 || true)"
if [ -n "$BUNX_BIN" ]; then
  chmod +x "$BUNX_BIN"
  ln -sf "$BUNX_BIN" /usr/local/bin/bunx
fi

command -v bun
bun --version

echo "== clone gbrain =="
rm -rf /opt/gbrain

if ! git clone --depth=1 --branch "$GBRAIN_REF" "$GBRAIN_REPO" /opt/gbrain; then
  echo "WARN: git clone with branch failed, fallback to default branch"
  git clone --depth=1 "$GBRAIN_REPO" /opt/gbrain
fi

test -f /opt/gbrain/package.json

cd /opt/gbrain

echo "== inspect package =="
node - <<'NODE'
const fs = require("fs");
const pkg = JSON.parse(fs.readFileSync("package.json", "utf8"));
console.log("name:", pkg.name);
console.log("bin:", JSON.stringify(pkg.bin || null, null, 2));
console.log("scripts:", JSON.stringify(pkg.scripts || null, null, 2));
NODE

echo "== install dependencies =="
if [ -f package-lock.json ]; then
  npm ci || npm install
else
  npm install
fi

echo "== install gbrain globally by npm =="
npm install -g .

echo "== check global gbrain =="
if ! command -v gbrain >/dev/null 2>&1; then
  echo "WARN: npm did not create gbrain command, creating wrapper from package.json bin"

  BIN_REL="$(node - <<'NODE'
const fs = require("fs");
const pkg = JSON.parse(fs.readFileSync("package.json", "utf8"));
const bin = pkg.bin;
if (typeof bin === "string") {
  console.log(bin);
} else if (bin && bin.gbrain) {
  console.log(bin.gbrain);
} else if (bin && Object.keys(bin).length > 0) {
  console.log(bin[Object.keys(bin)[0]]);
}
NODE
)"

  test -n "$BIN_REL"
  BIN_ABS="/opt/gbrain/$BIN_REL"
  test -f "$BIN_ABS"

  cat > /usr/local/bin/gbrain <<EOF
#!/usr/bin/env bash
set -e
cd /opt/gbrain
export PATH="/opt/bun/bin:/usr/local/bin:\$PATH"
exec bun "$BIN_ABS" "\$@"
EOF

  chmod +x /usr/local/bin/gbrain
fi

echo "== final verify =="
command -v gbrain
ls -l "$(command -v gbrain)"
gbrain --help 2>&1 | head -80 || true

chmod -R a+rX /opt/bun /opt/gbrain

echo "OK: gbrain installed"
```

要求：

```bash
chmod +x docker/install-gbrain.sh
```

### 6.2 Dockerfile 替换 GBrain 安装段

删除旧逻辑：

```dockerfile
RUN if [ "${INSTALL_GBRAIN}" = "1" ]; then \
      (curl -fsSL https://bun.sh/install | bash -s -- bun-v1.2.15 \
        && ln -sf /root/.bun/bin/bun /usr/local/bin/bun \
        && ln -sf /root/.bun/bin/bunx /usr/local/bin/bunx \
        && bun install -g "${GBRAIN_REPO}" \
        && echo "OK: gbrain installed") \
      || echo "WARN: gbrain install failed; init-brain-runtime.sh will skip gbrain."; \
    fi
```

替换为：

```dockerfile
ARG INSTALL_GBRAIN=1
ARG GBRAIN_REPO=http://git.superic.com/aiplatform/gbrain.git
ARG GBRAIN_REF=master
ARG BUN_VERSION=bun-v1.2.15

ENV BUN_INSTALL=/opt/bun
ENV PATH=/opt/bun/bin:/usr/local/bin:$PATH

COPY docker/install-gbrain.sh /usr/local/bin/install-gbrain.sh

RUN chmod +x /usr/local/bin/install-gbrain.sh \
  && INSTALL_GBRAIN="${INSTALL_GBRAIN}" \
     GBRAIN_REPO="${GBRAIN_REPO}" \
     GBRAIN_REF="${GBRAIN_REF}" \
     BUN_VERSION="${BUN_VERSION}" \
     /usr/local/bin/install-gbrain.sh
```

### 6.3 Dockerfile 权限段补充

原权限段需要包含：

```text
/opt/bun
/opt/gbrain
```

目标：

```dockerfile
RUN mkdir -p /data/hermes /workspace /uv_cache /app \
  && touch /app/venv/.deps_installed \
  && chown -R hermeswebui:hermeswebui \
      /data \
      /workspace \
      /uv_cache \
      /app \
      /app/venv \
      /home/hermeswebui/.hermes \
      /opt/hermes-agent \
      /opt/bun \
      /opt/gbrain \
  && chmod -R u+rwX,g+rwX \
      /data \
      /workspace \
      /uv_cache \
      /app \
      /app/venv \
      /home/hermeswebui/.hermes \
      /opt/bun \
      /opt/gbrain
```

### 6.4 Dockerfile 构建失败原则

禁止吞掉 GBrain 安装失败。

不允许：

```dockerfile
|| echo "WARN: gbrain install failed"
```

允许：

```bash
command -v gbrain
```

作为构建验收。

若 GBrain 安装失败，Docker build 必须失败。

## 11. 新增 rebuild-shared-image.sh

新增：

```text
scripts/rebuild-shared-image.sh
```

用途：只构建一次共享镜像，避免每个实例重复 build。

内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

PROFILE="${1:-zhang-zhen}"
BUILD_FLAG="${2:---no-cache}"

BASE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
ENV_FILE="$BASE_DIR/instances/$PROFILE/.env"

[ -f "$ENV_FILE" ] || {
  echo "ERROR: missing env file: $ENV_FILE"
  exit 1
}

cd "$BASE_DIR"

IMAGE_NAME="$(grep '^LOCAL_IMAGE_NAME=' "$ENV_FILE" | cut -d= -f2-)"
IMAGE_NAME="${IMAGE_NAME:-hermes-agent-webui:latest}"

if [ "$BUILD_FLAG" = "--no-cache" ]; then
  docker compose --env-file "$ENV_FILE" \
    -p hermes-image-build \
    build --no-cache --pull --progress=plain
else
  docker compose --env-file "$ENV_FILE" \
    -p hermes-image-build \
    build --pull --progress=plain
fi

echo "== built image =="
docker image inspect "$IMAGE_NAME" \
  --format 'IMAGE={{.RepoTags}} ID={{.Id}} CREATED={{.Created}}'

bash "$BASE_DIR/scripts/doctor-image.sh" "$IMAGE_NAME"

echo "OK: shared image rebuilt and verified: $IMAGE_NAME"
```

授权：

```bash
chmod +x scripts/rebuild-shared-image.sh
```

## 12. 新增 recreate-all-instances.sh

新增：

```text
scripts/recreate-all-instances.sh
```

用途：让所有实例使用最新共享 image，但不重复 build。

内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

BASE_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
cd "$BASE_DIR"

for ENV_FILE in instances/*/.env; do
  PROFILE="$(basename "$(dirname "$ENV_FILE")")"

  echo "== recreate hermes-$PROFILE =="
  docker compose --env-file "$ENV_FILE" \
    -p "hermes-$PROFILE" \
    up -d --no-build --force-recreate
done

echo "== containers =="
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}'
```

授权：

```bash
chmod +x scripts/recreate-all-instances.sh
```
