# 2. 源码现状

当前 `copilot-docker` 用于部署多个独立 Hermes 实例，每个实例拥有独立的 `HERMES_HOME`、workspace、sessions、skills 和 memories。实例通过 `create-instance.sh` 创建，通过 `up-instance.sh` 启动，并通过专家模板注入角色能力。([GitHub][1])

当前公共脚本的实际职责如下：

```text
scripts/create-instance.sh
├── 创建实例目录
├── 生成实例 .env
├── 初始化 data/hermes
├── 调用 scripts/inject-expert.sh
└── 调用 scripts/sync-runtime-env.sh
```

```text
scripts/up-instance.sh
├── 迁移实例环境变量
├── 同步 Runtime 环境变量
├── 初始化公共运行目录
├── 构建或复用 Docker 镜像
├── 启动 Docker Compose
└── 输出 WebUI 与 Agent API 地址
```

`create-instance.sh` 当前仍直接依赖公共 `inject-expert.sh`，`up-instance.sh` 当前没有专家包生命周期调用。([GitHub][2])

v1.10 已确定以下目录边界：

```text
expert-templates/bi-strategic-office/
├── expert.yaml
├── runtime/
├── plugins/
├── bin/
├── lib/
├── tests/
├── docs/
└── prd/
```

v1.11 延续该结构，不重新拆散专家包。

# 3. 改造背景

当前 `bi-strategic-office` 自研问数插件承担了：

* 数据源定义；
* 表字段语义；
* 表关联关系；
* 自然语言解析；
* SemanticQuery；
* SQL 编译；
* SQL 执行；
* 查询状态；
* 结果标准化；
* 图表推荐。

实际运行中已经出现：

* 显式过滤条件丢失；
* 默认时间范围错误；
* 明细查询误返回全局数据；
* followup 查询状态丢失；
* 本地模型工具调用不稳定；
* 配置和测试成本持续上升。

SQLBot 已经提供：

* 表和字段管理；
* 字段别名和业务描述；
* 表关系管理；
* 自定义术语；
* SQL 示例；
* Text-to-SQL；
* 查询执行；
* 图表生成；
* 数据明细；
* SQL 查看；
* 多轮上下文；
* 工作空间；
* 行列权限；
* MCP 集成。([SQLBot][3])

本次不再维护完整自研问数引擎。

---

# 4. 改造目标

完成以下结果：

1. SQLBot 作为独立问数服务运行。
2. Hermes 通过 MCP 调用 SQLBot。
3. 模型不直接看到 SQLBot 登录、Token 和 `chat_id`。
4. `hermes-finance-bi-plugin` 替换为轻量的 `hermes-sqlbot-adapter`。
5. 保留现有财务分析、报告编排、附件分析和数据质量检查能力。
6. SQLBot 负责数据查询，Hermes 负责结果分析。
7. SQLBot 的表、字段、关系、术语和 SQL 示例由实施人员在 SQLBot 中配置。
8. SQLBot 配置完成后，在专家包内创建 `sqlbot-example.md`。
9. 不修改 SQLBot 源码。
10. 不修改 SQLBot 数据库内部表。
11. 不在 `copilot-docker` 中复制 SQLBot 源码。
12. 不修改 Hermes Agent 核心代码。
13. 不影响 `writer`、`finance`、`sale` 等现有专家。

# 11. Hermes 工具设计

Adapter 注册 Toolset：

```text
finance-bi
```

模型只看到四个工具。

## 11.1 `finance_bi_ask`

用途：

* 发起新的数据查询；
* 在当前 Hermes 会话尚无 SQLBot 对话时创建 `chat_id`；
* 返回查询结果。

输入：

```json
{
  "question": "查询2026Q2各产品销售利润",
  "datasource_key": "finance-sales-profit",
  "response_mode": "data_and_summary"
}
```

字段要求：

| 字段               | 必填 | 说明                                     |
| ---------------- | -: | -------------------------------------- |
| `question`       |  是 | 用户原始问题                                 |
| `datasource_key` |  否 | 配置中的数据源别名                              |
| `response_mode`  |  否 | `data_only`、`data_and_summary`、`chart` |

不得让模型传递 SQLBot `datasource_id`。

---

## 11.2 `finance_bi_followup`

用途：

* 使用当前 SQLBot `chat_id` 继续追问。

输入：

```json
{
  "instruction": "只看毛利率低于5%的产品"
}
```

Adapter 内部读取：

```text
Hermes session_id
→ SQLBot chat_id
```

不存在会话时返回：

```json
{
  "success": false,
  "error": {
    "code": "QUERY_CONTEXT_NOT_FOUND",
    "message": "当前会话没有可继续的问数记录，请先发起一次查询。"
  }
}
```

---

## 11.3 `finance_bi_explain`

用途：

* 解释最近一次查询；
* 返回 SQL、数据源、筛选条件、表和字段信息；
* 不重新查询数据库。

输入：

```json
{
  "query_id": "optional"
}
```

---

## 11.4 `finance_bi_reset`

用途：

* 清除 Hermes Session 与 SQLBot `chat_id` 的映射；
* 下一次查询重新创建 SQLBot 对话。

# 12. 会话管理

## 12.1 状态存储

路径：

```text
/data/hermes/sqlbot-adapter/state/sqlbot_sessions.db
```

SQLite 表至少保存：

```text
hermes_profile
hermes_session_id
hermes_user_id
sqlbot_chat_id
sqlbot_workspace_id
sqlbot_datasource_id
token_encrypted
token_expires_at
last_query_id
created_at
updated_at
expires_at
```

## 12.2 会话隔离

映射键：

```text
Hermes Profile
+ Hermes Session ID
+ Hermes User ID
```

禁止所有用户共用一个 SQLBot `chat_id`。

## 12.3 生命周期

* 首次查询：登录 SQLBot并创建对话；
* 后续查询：复用有效 Token 和 `chat_id`；
* Token 过期：重新登录；
* `chat_id` 失效：新建对话并返回上下文重建提示；
* `/new` 或 `/reset`：清除映射；
* 会话过期：默认 24 小时；
* 使用 SQLite WAL；
* 所有写入必须 commit 后再返回 Tool Result。

# 13. 查询保护

SQLBot 配置完善后仍可能出现筛选、关联或统计范围偏差。SQLBot 官方也要求通过表字段说明、关系、术语和 SQL 示例持续校准。([SQLBot][4])

Adapter 必须保留保护层。

## 13.1 SQL 类型检查

只允许：

```text
SELECT
WITH ... SELECT
```

拒绝：

```text
INSERT
UPDATE
DELETE
MERGE
DROP
ALTER
TRUNCATE
CALL
COPY
多语句
```

## 13.2 显式标识符检查

用户问题包含以下形式时：

```text
ar_trx_number = 101IN26070199
凭证号 101IN26070199
订单号 XXX
客户编号 XXX
```

Adapter 提取显式标识符，并检查 SQLBot 返回 SQL 是否保留该值。

未保留时：

```json
{
  "success": false,
  "error": {
    "code": "FILTER_NOT_PRESERVED",
    "message": "生成的查询未保留用户明确指定的过滤条件，已终止返回数据。"
  }
}
```

不得返回全局前若干行数据。

## 13.3 明细查询约束

明细查询至少满足一个条件：

* 精确编号；
* 明确日期范围；
* 明确客户；
* 明确主体；
* SQLBot 权限规则限定范围。

否则返回：

```text
DETAIL_QUERY_REQUIRES_FILTER
```

## 13.4 结果限制

配置：

```text
默认返回模型的行数：100
最大返回模型的行数：500
完整结果：保留在 SQLBot 或导出文件
```

避免将大结果集完整放入 Hermes 上下文。

# 15. 错误码

| 错误码                            | 含义              |
| ------------------------------ | --------------- |
| `SQLBOT_NOT_CONFIGURED`        | 缺少 SQLBot 配置    |
| `SQLBOT_UNAVAILABLE`           | SQLBot 服务不可访问   |
| `SQLBOT_AUTH_FAILED`           | SQLBot 登录失败     |
| `WORKSPACE_NOT_FOUND`          | 工作空间不存在         |
| `DATASOURCE_NOT_FOUND`         | 数据源不存在          |
| `QUERY_CONTEXT_NOT_FOUND`      | 没有可继续的上下文       |
| `QUERY_GENERATION_FAILED`      | SQLBot 未生成有效查询  |
| `QUERY_EXECUTION_FAILED`       | SQLBot 执行查询失败   |
| `FILTER_NOT_PRESERVED`         | 显式筛选条件未保留       |
| `UNSAFE_SQL`                   | SQL 不符合只读要求     |
| `DETAIL_QUERY_REQUIRES_FILTER` | 明细查询缺少有效过滤      |
| `RESULT_TOO_LARGE`             | 结果超过限制          |
| `SQLBOT_RESPONSE_INVALID`      | SQLBot 返回结构无法解析 |
| `INTERNAL_ERROR`               | Adapter 内部错误    |

Tool handler 必须返回 JSON 字符串，不得把异常抛给 Hermes Agent Loop。

# 19. SOUL 与 Skill 调整

## 19.1 SOUL.md

增加固定规则：

```text
1. 所有数据库问数必须调用 finance-bi 工具。
2. 不得通过 terminal 直接连接数据库。
3. 不得自行生成并执行 SQL。
4. 不得把 SQLBot 认证信息输出给用户。
5. SQLBot 返回数据后，必须区分原始事实和分析判断。
6. 查询中包含明确编号时，结果必须保留该编号条件。
7. Adapter 返回安全错误时，不得绕过后重新取数。
8. 不得将查询结果写入长期记忆。
```

## 19.2 `finance-bi-query`

负责：

* 识别问数请求；
* 选择 `finance_bi_ask` 或 `finance_bi_followup`；
* 明确数据源；
* 输出时间、主体、币种和口径。

## 19.3 `sqlbot-query-review`

负责：

* 检查 SQLBot SQL；
* 检查筛选条件；
* 检查结果范围；
* 识别无关数据；
* 发现问题时停止分析。

## 19.4 `finance-performance-analysis`

继续负责：

* 同比环比；
* 利润变化；
* 客户贡献；
* 产品贡献；
* 异常归因；
* 管理层摘要。

不负责查询数据库。
