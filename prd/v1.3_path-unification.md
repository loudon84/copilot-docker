# PRD：copilot-docker 路径统一治理

版本：`copilot-docker_v1.3_path-unification`

## 1. 目标

统一 `copilot-docker` 中 Hermes 实例目录规则，解决以下问题：

* `tools/tools -> /data/hermes/tools` 自循环软链。
* `/home/hermeswebui/.hermes/tools` 被误删时报 `Device or resource busy`。
* `/opt/hermes-agent/tools`、`~/.hermes/tools`、`/data/hermes/tools` 混用。
* `export-assets.sh` 导出缺文件。
* `import-assets.sh` 反复创建错误软链。
* 新实例缺少 `tools/plugins` 目录。
* UID/GID 1000 与 1024 权限冲突。
* build context 扫描 `instances/` 导致构建失败。

## 2. 统一目录规则

### 2.1 唯一实例资产主目录

所有实例可复制、可持久化资产只放：

```text
/data/hermes/
├── skills/
├── tools/
├── plugins/
├── mcp/
├── policies/
├── skill-bundles/
└── gbrain/
```

宿主机对应：

```text
instances/<profile>/data/hermes/
```

### 2.2 兼容路径只允许由 compose 挂载

以下路径只作为兼容入口：

```text
/home/hermeswebui/.hermes/tools
/home/hermeswebui/.hermes/plugins
```

它们必须通过 `docker-compose.yml` bind mount 到：

```text
/data/hermes/tools
/data/hermes/plugins
```

禁止脚本在容器内删除、重建、软链这两个路径。

### 2.3 镜像源码路径不参与实例资产分发

以下路径只属于基础镜像：

```text
/opt/hermes-agent
/opt/hermes-agent/tools
/home/hermeswebui/.hermes/hermes-agent
```

规则：

* 不作为 asset bundle 默认导出来源。
* 不作为新同事实例资产目录。
* 如果有历史工具在 `/opt/hermes-agent/tools`，先迁移到 `/data/hermes/tools`，再导出。
* 通用工具应进入 Dockerfile 或 expert template，不应靠容器内手工复制。

## 4. Dockerfile 修复要求

### 4.1 固定运行用户

最终运行用户必须是：

```text
UID=1000
GID=1000
```

Dockerfile 中必须保证：

```dockerfile
groupadd -g 1000 hermeswebui
useradd -u 1000 -d /home/hermeswebui -g hermeswebui -s /bin/bash -m hermeswebui
```

最终必须：

```dockerfile
USER hermeswebui
```

或：

```dockerfile
USER 1000:1000
```

### 4.2 权限统一

必须对以下目录执行：

```dockerfile
chown -R 1000:1000 \
  /data \
  /workspace \
  /uv_cache \
  /app \
  /app/venv \
  /home/hermeswebui/.hermes \
  /opt/hermes-agent
```

### 4.3 `/opt/hermes-agent` 只保留源码用途

允许：

```text
/opt/hermes-agent
/home/hermeswebui/.hermes/hermes-agent -> /opt/hermes-agent
```

不允许把 `/opt/hermes-agent/tools` 当实例工具目录。

## 5. docker-compose.yml 修复要求

### 5.1 volumes 固定为三条

```yaml
volumes:
  - ./instances/${HERMES_PROFILE:-default}/data/hermes:/data/hermes
  - ./instances/${HERMES_PROFILE:-default}/data/hermes/tools:/home/hermeswebui/.hermes/tools
  - ./instances/${HERMES_PROFILE:-default}/data/hermes/plugins:/home/hermeswebui/.hermes/plugins
```

不得再增加：

```yaml
- ./shared/hermes-agent:/opt/hermes-agent
- ./shared/hermes-tools:/home/hermeswebui/.hermes/tools
```

除非另起专门的开发模式 compose。

### 5.2 用户固定

```yaml
user: "1000:1000"
```

### 5.3 WANTED_UID/GID 固定

```yaml
WANTED_UID: "1000"
WANTED_GID: "1000"
```

不要使用：

```yaml
WANTED_UID: ${UID:-1000}
WANTED_GID: ${GID:-1000}
```

避免宿主机环境污染。

### 5.4 环境变量统一

增加：

```yaml
HERMES_TOOLS_PATH: /data/hermes/tools
HERMES_PLUGINS_PATH: /data/hermes/plugins
HERMES_SKILLS_PATH: /data/hermes/skills
HERMES_WORKSPACE_PATH: /data/hermes/workspace
```

## 9. up-instance.sh 修复要求

### 9.1 启动前校验目录

`docker compose up -d` 前必须检查：

```bash
DATA_DIR="$BASE_DIR/instances/$PROFILE/data/hermes"

mkdir -p \
  "$DATA_DIR/tools" \
  "$DATA_DIR/plugins" \
  "$DATA_DIR/skills" \
  "$DATA_DIR/mcp" \
  "$DATA_DIR/policies" \
  "$DATA_DIR/skill-bundles" \
  "$DATA_DIR/gbrain"

rm -f "$DATA_DIR/tools/tools" 2>/dev/null || true
rm -f "$DATA_DIR/plugins/plugins" 2>/dev/null || true

chown -R 1000:1000 "$DATA_DIR/tools" "$DATA_DIR/plugins" "$DATA_DIR/skills" 2>/dev/null || true
chmod -R u+rwX,g+rwX "$DATA_DIR/tools" "$DATA_DIR/plugins" "$DATA_DIR/skills" 2>/dev/null || true
```

### 9.2 启动后检查

启动后检查：

```bash
docker inspect "hermes-$PROFILE"
docker logs --tail=80 "hermes-$PROFILE"
```

如果容器状态为 `restarting`，脚本返回非 0。

## 10. export-assets.sh 修复要求

### 10.1 默认只导出 `/data/hermes`

允许导出：

```text
/data/hermes/skills
/data/hermes/tools
/data/hermes/plugins
/data/hermes/mcp
/data/hermes/policies
/data/hermes/skill-bundles
/data/hermes/gbrain
```

禁止默认导出：

```text
/home/hermeswebui/.hermes/tools
/home/hermeswebui/.hermes/plugins
/opt/hermes-agent/tools
/opt/hermes-agent/plugins
```

### 10.2 删除错误逻辑

删除类似：

```bash
copy_dir /home/hermeswebui/.hermes/tools tools
copy_dir /home/hermeswebui/.hermes/plugins plugins
```

这是造成 `tools/tools` 的直接原因。

### 10.3 增加毒包检测

导出后必须检查：

```bash
tar tzf "$OUT_DIR/data-hermes-assets.tgz" | grep -E '(^|/)tools/tools($|/)|(^|/)plugins/plugins($|/)' && {
  echo "ERROR: invalid nested tools/plugins path"
  exit 1
}
```

### 10.4 历史工具迁移参数

允许增加参数：

```bash
--migrate-agent-tools
```

含义：

* 从 `/opt/hermes-agent/tools` 复制指定白名单工具到 `/data/hermes/tools`。
* 再从 `/data/hermes/tools` 导出。
* 不直接把 `/opt/hermes-agent/tools` 打进 bundle。

白名单文件放：

```text
asset-bundles/<bundle>/agent-tools.include
```

## 11. import-assets.sh 修复要求

### 11.1 只解压到宿主机目标目录

导入目标固定：

```text
instances/<profile>/data/hermes
```

解压：

```bash
tar xzf "$BUNDLE_DIR/data-hermes-assets.tgz" -C "$TARGET_DIR"
```

### 11.2 不删除 mountpoint

禁止：

```bash
rm -rf /home/hermeswebui/.hermes/tools
rm -rf /home/hermeswebui/.hermes/plugins
ln -sfn /data/hermes/tools /home/hermeswebui/.hermes/tools
ln -sfn /data/hermes/plugins /home/hermeswebui/.hermes/plugins
```

### 11.3 容器内只做检查

如果容器运行中，只允许：

```bash
test -d /data/hermes/tools
test -d /data/hermes/plugins
mountpoint -q /home/hermeswebui/.hermes/tools || echo "warn"
mountpoint -q /home/hermeswebui/.hermes/plugins || echo "warn"
```

不得修改这两个 mountpoint。

### 11.4 导入前清理错误嵌套

```bash
rm -f "$TARGET_DIR/tools/tools" 2>/dev/null || true
rm -f "$TARGET_DIR/plugins/plugins" 2>/dev/null || true
```

导入后再清理一次。

### 11.5 安装依赖

Python 依赖：

```bash
/app/venv/bin/python -m pip install -r /tmp/hermes-bundle-requirements.txt
```

不得使用系统 pip。

## 17. 新增脚本：scripts/doctor-paths.sh

### 17.1 用法

```bash
bash scripts/doctor-paths.sh <profile>
```

### 17.2 检查项

```text
1. instances/<profile>/data/hermes 存在
2. tools/plugins/skills/mcp/policies/skill-bundles/gbrain 存在
3. 不存在 tools/tools
4. 不存在 plugins/plugins
5. 宿主机目录 owner 可写
6. 容器存在时：
   - /data/hermes/tools 存在
   - /data/hermes/plugins 存在
   - ~/.hermes/tools 是 mountpoint
   - ~/.hermes/plugins 是 mountpoint
   - UID=1000
   - GID=1000
   - /app/venv 可写
```

### 17.3 自动修复参数

```bash
bash scripts/doctor-paths.sh <profile> --fix
```

`--fix` 只允许修：

```text
创建缺失目录
删除 tools/tools
删除 plugins/plugins
chown 1000:1000
chmod u+rwX,g+rwX
```

不得删除 mountpoint。
